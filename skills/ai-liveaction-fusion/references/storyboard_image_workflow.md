# 静态分镜在前、视频生成在后的两阶段工作流

## 0. 标准输入

新项目从以下原始来源开始：
- 用户确认的项目要求；
- 剧本 / Shot List / 镜头说明；
- 原视频及原声、时间码和可见片场批注；
- 场景、人物、服装、配饰、道具及 VFX / 质感资产。

静态提示词和视频提示词均在流程中后续生成，不属于标准输入，也不得反向充当镜头事实来源。

## 1. 状态机

每个需要分镜图的镜头按以下状态推进：

`场景拓扑待核验 → 镜头投影待核验 → 事实待核验 → 静态提示词待确认 → 候选图生成中 → 候选图待审 → 单变量返修 / 候选通过 → 等待用户发布 → /分镜图本地映射完成 → 视频提示词已编译`

若用户要求平台执行，再按独立状态推进：`平台素材已上传 / 可选 → 提示词已填入 → 正文真实 mention 已绑定 → 经明确授权后提交生成 → 视频 Take 待审`。没有提交授权时停在“正文真实 mention 已绑定、未提交”。

不得跳过的门禁：
- 没有镜头事实卡，不编译静态提示词；
- 没有镜头—场景投影字段，或高影响角度 / 主导表面仍待确认，不编译静态提示词或调用生图；
- 用户未确认提示词与参考图，不调用生图；
- 候选图未由用户发布到 `/分镜图`，不获得 `@分镜图` 权威；
- 标记“需分镜图”的镜头未完成本地文件映射，不编译最终视频提示词。

## 2. 目录职责

- `镜头事实/`：镜头事实卡与来源记录；
- `静态分镜/待确认/`：静态提示词与参考图清单；
- `静态分镜/生成结果/`：所有候选 Take；
- `静态分镜/返修记录/`：失败证据与单变量返修；
- `/分镜图/`：用户筛选、优化并正式发布的分镜图；Agent 默认只读；
- `视频提示词/`：使用已绑定分镜图重新编译的视频提示词。

项目可改目录名，但“候选目录”和“人工发布目录”必须物理分离。

## 3. 静态分镜阶段

1. 从原视频定位镜头 ID、时间码和关键帧，并读取同镜头前邻帧、后邻帧；不得只分析一张截图。
2. 把场景资产拆成地面、墙面、天花 / 天空、门窗、固定锚点、邻接关系和资产原视角，建立场景拓扑。
3. 建立镜头—场景投影：摄影机高度 / 俯仰、人物屏幕空间姿态与接触、主导可见表面、上中下分区、地墙交界 / 地平线、资产表面重投影和明确排除项。
4. 建立镜头事实卡，区分静态视觉事实与时间运动事实。
5. 判断是否需要分镜图；无需分镜图的镜头记录原因。
6. 选择最少充分参考图并声明每张图负责 / 不负责；场景图同时标记“同方向权威 / 仅拓扑 / 仅材质 / 当前方向排除”；核验当前工具的参考图、格式、尺寸和并发上限，超限时按职责排序且不得静默丢弃关键参考。
7. 用 `scripts/validate_camera_scene_projection_card.py` 验证投影字段；`FAIL` 修卡，`BLOCKED` 先确认，只有 `PASS` 才从静态视觉事实和投影字段编译固定十标题图像编辑提示词。
8. 先向用户展示提示词、参考图清单和高影响投影判断。
9. 用户确认后调用生图工具，输出到候选目录；并行生成时逐镜持久化结果，一个任务失败不得抹掉已成功的同批产物。
10. 审查真实候选图；投影角度、主导表面、人物姿态拓扑、空间边界归属或任一可见人物状态回退均为硬失败；返修时一次只修一个主变量。
11. 更新候选状态清单，登记每个版本、QC、当前最佳候选和被替代原因；“当前最佳”仍是候选，不获得正式 `/分镜图` 权威。
12. 报告候选图，不自动发布。

## 4. 用户筛选阶段

用户可以：
- 从多个 Take 中选择；
- 在外部工具中修图；
- 更名、裁切或优化；
- 把最终文件保存到 `/分镜图`。

Agent 不能依据“看起来不错”自动晋级。只有用户明确说明筛选完成，或明确指定某个候选文件并要求发布，才能进入绑定阶段。

## 5. 分镜图发布与本地映射阶段

逐项核验：
- 文件真实存在；
- 镜头 ID 和关键帧状态可识别；
- 画幅与目标视频一致；
- 不含时间码、水印、技术字或错误人物；
- 同一镜头多文件时，用户已指定权威版本；
- 文件内容没有与镜头事实卡冲突。
- 摄影机角度、人物姿态 / 接触拓扑、主导背景表面和地墙关系与镜头—场景投影一致。

生成本地映射清单：`镜头 ID → 关键帧 → /分镜图 文件 → 运行时 @句柄 → 状态`。它证明正式分镜文件与语义句柄的映射，不证明生成平台正文中的真实 mention / token 已绑定。

## 6. 视频提示词阶段

视频提示词从镜头事实卡重新编译，而不是从静态提示词扩写：
- 继承静态视觉事实；
- 恢复时间、动作、运镜、接触、受力、VFX 触发和连续性；
- 恢复首 / 中 / 尾帧的摄影机俯仰、主导可见表面、地平线 / 地墙交界和视差变化；
- 绑定用户批准的 `@分镜图`；
- 明确 `@分镜图` 负责关键帧视觉结果，不负责重演动态；
- 当一个视频镜头有多个关键状态时，可绑定首帧 / 中间 / 尾帧多张分镜图，并写清各自时间职责。

若继续在生成平台落地，读取 `platform_asset_binding_rules.md`。纯文本 `@句柄` 只视为待绑定语义；必须将正文每次引用解析为可验证的真实素材引用，并把上传、填词、绑定与提交分别报告。

## 7. 返修边界

- 静态 Take 失败：修静态提示词、参考图职责或单帧空间判断；
- 视频 Take 失败：修时间运动、连续性、参考绑定或视频逐镜；
- 若分镜图本身的摄影机角度、人物姿态或场景投影错误：退回静态阶段，由用户重新发布后再编译视频提示词；
- 不在视频提示词中用大量文字补救一张已知错误的分镜图。
