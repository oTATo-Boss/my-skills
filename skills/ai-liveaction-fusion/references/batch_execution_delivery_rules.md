# 批量执行、状态统计与交付规则

本文件用于多镜头、多集数或多单元批量生产。它不放宽镜头事实、投影、提示词确认、正式分镜图或视频授权门禁。

## 1. 批量单位

- 批量调度单位是“单镜自包含任务包”，不是一个共享大提示词。
- 互不依赖的镜头可以并行，但每镜必须独立绑定唯一底图、参考资产、提示词、候选目录和审查记录。
- 并行不能让多个镜头共用一个模糊的参考图集合，也不能把 A 镜资产或审查写入 B 镜。
- 受工具并发、费用、平台限制或失败风险影响时，使用有界并发；失败重试只针对缺失或明确失败的镜头。

### 工具能力预检与参考图预算

批量启动前读取当前生成工具的实际能力：单次参考图上限、支持格式、输入与输出尺寸、并发上限、返回值结构和内容审核行为。工具限制可能随环境变化，不把历史数值当成永久常量。

参考图超限时不得静默丢弃。逐镜优先级为：

1. 唯一编辑底图；
2. 当前摄影方向 / 边界拓扑最权威的场景图；
3. 主体人物完整身份、服装与状态；
4. 其他实际可见人物的身份、服装与状态；
5. 当前帧关键道具、VFX 或材质参考。

同一职责可使用经过核验的参考拼图节省槽位；仍超限时改为分步编辑或把高影响缺口标为阻塞。不得让非底图参考取代唯一编辑底图，不得省略后假装已经绑定。

## 2. 批量准备顺序

1. 枚举用户指定的全部实拍原图并建立源图清单。
2. 映射镜头 ID、时间码和事实卡；高影响映射不确定时标记待确认。
3. 先补齐全批次镜头事实和镜头—场景投影门禁。
4. 为每张目标原图建立自包含任务包，复制最少充分参考资产。
5. 编写逐镜提示词和参考图职责清单。
6. 更新批量任务总表并交用户确认。
7. 只生成已获用户确认的任务包。
8. 每个真实候选图生成后进行实际审查，记录通过、局部通过/待修或不通过。
9. 建立 `templates/candidate_status_manifest_template.md` 候选状态清单，逐版本登记实际文件、生成状态、QC、当前最佳候选和替代原因。

## 3. 并行结果隔离与部分成功

- 并行调用使用逐镜独立结果槽和 all-settled 等价语义：成功、失败、审核拦截和超时分别记录，不以单个异常覆盖整组状态。
- 每张候选一旦返回就先保存并登记，再汇总批次结果；不得等整组全部成功后才统一落盘。
- 批次报错后先扫描候选目录、工具返回值和当次实际生成产物，再判断缺失镜头；整组调用失败不等于整组零产物。
- 只重试确认缺失或明确失败的镜头。发现同批已成功产物时纳入候选状态清单，不重复消耗生成额度。
- 安全审核失败与技术失败分别记录；平台兼容改写只影响对应镜头，不污染同批其他提示词。

## 4. 六个独立计数

批量状态必须分别统计：

1. **源图数**：用户指定进入本批次的实拍原图数量。
2. **任务包数**：已建立的自包含分镜目录数量。
3. **候选覆盖**：至少存在一张实际候选图的任务包数量。
4. **候选版本总数**：所有任务包内实际候选图片文件总数。
5. **审查覆盖**：至少存在一份非空审查 Markdown 的任务包数量。
6. **正式分镜图覆盖**：已由用户发布并进入绑定清单的镜头数量。

不得用候选版本总数代替候选覆盖。例如一个镜头有三个版本，仍只贡献一个候选覆盖。

## 5. 完成状态

- `候选覆盖 < 源图数`：**生成中**。
- `候选覆盖 = 源图数`：**已完成（生图）**。
- `候选覆盖 = 审查覆盖 = 源图数`：**已完成（生图+审查）**。
- 正式分镜图和视频阶段另行统计，不影响“生图已完成”的判断。

QC 结论单独汇报：

- `通过`
- `局部通过 / 待修`
- `不通过`

局部待修或不通过不会把“候选覆盖已经完成”改回“生成中”；它们表示质量状态，不表示图片不存在。

任务线程的 `active / idle / completed` 是执行状态，不是产物完成权威。线程仍 active 但文件已完整落盘时，按实际落盘标记生图或审查完成；线程结束但仍缺候选图时，仍标记未完成。

## 6. 审查的含义

审查必须查看真实候选图，并对照唯一底图、事实卡、投影卡、提示词和参考资产，至少判断：

- 原演员身份是否保持；
- 构图、景别、机位和人物占比是否保持；
- 姿态、接触、遮挡与受力拓扑是否保持；
- 场景方向、主导可见表面和地墙关系是否正确；
- 服装、妆造、道具和 VFX 是否按职责替换；
- 所有可见人物，包括非修改目标、越肩、前景局部和背景人物，是否保持已确认状态；
- 光线、材质、景深和融合是否成立；
- 时间码、绿幕、技术字和片场元素是否清除。

一份审查 Markdown 只证明已经检查，不等于可用。可用性由 QC 结论表达。

## 7. 候选版本与当前最佳

- 每个分镜包维护一份候选状态清单；`current_best` 只能指向实际存在且已经审查的候选文件。
- 新版本生成后不得覆盖旧版本；若取代原 `current_best`，记录取代理由和旧版本的 `superseded_by`。
- 没有足够证据时 `current_best` 写 `未确定`，不得仅按最新文件时间自动选择。
- `current_best` 是便于协作和导出的候选推荐，不等于用户发布的正式 `/分镜图`。

## 8. 断点续跑

- 续跑前先重新扫描实际文件，不沿用旧汇报数字。
- 已有候选图的任务包默认跳过，除非用户明确要求返修或重生。
- 只处理缺图、缺审查或用户指定待修的镜头。
- 不因监控任务、旧线程或历史总表显示“待生成”而重复生成已经落盘的镜头。
- 失败重试记录失败原因和已尝试版本；不要无限重试同一错误提示词。

## 9. 进度汇报

每集或每批次至少汇报：

- 候选覆盖 `x/y`
- 候选版本总数
- 当前最佳候选覆盖与未裁决镜头
- 审查覆盖 `x/y`
- 剩余镜头 ID
- 当前完成状态
- 任务是否仍运行
- 明确失败或阻塞

当多个来源冲突时，权威顺序为：实际落盘文件 → 当前任务的最新有效结果 → 批量总表 → 旧进度消息。

## 10. 输出技术预检

候选进入审查、导出或正式绑定前，核验：

- 宽高比是否在目标容差内；平台要求精确像素时，实际像素必须匹配，不能只凭“9:16”等标签判断；
- 文件可读、方向标记正确、色彩模式与目标平台兼容；
- 透明通道、色彩配置、文件大小和编码不会导致平台误读；
- 必要的裁切、转色或缩放采用非破坏方式生成新版本，保留原候选；不得用拉伸改变人物与场景比例。

技术预检通过不代表画面 QC 通过，两者分别记录。

## 11. 交付与导出

- 用户要求“导出生成图”但未指定精选版本时，默认导出所有实际候选图片版本，不替用户做最终筛选。
- 多集导出默认按集建立一级目录；用户要求平铺时，各集目录内直接放图片，不再建立逐镜子文件夹。
- 文件名保留镜头 ID 和版本号，避免同集冲突。
- 默认非覆盖复制；发现同名文件时先比较内容，内容一致可跳过，内容不一致不得静默覆盖。
- 用户明确说明某集已经导出时跳过，不重复复制。
- 导出后核对源文件数、导出文件数和内容一致性，并报告实际路径。
- 正式分镜图、候选图和视频 Take 必须分开交付；不得把候选导出行为解释为正式发布到 `/分镜图`。
