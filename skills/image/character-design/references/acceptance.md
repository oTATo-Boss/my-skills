# 资产验收与交接

## 写实模板用途验收

记录采用 `realistic-base`、`beauty`、`handsome` 或一步到位 `realistic/board.txt`。通用基础服装版检查普通T恤、长裤、鞋子与设定体型；帅哥版检查黑色短裤与完美身材；各自所有视图保持一致；美女版检查纯白色基础款合身短袖T恤和黑色基础款运动短裤（裤长至大腿中部），并按恢复后的原女模特模板验收审美、摄影与肤质；本次没有改写这些要求。一步到位综合板检查实际参考图及结尾设计插槽的要求是否落实，不套用默认基础服装。着装替代须说明原因与信息限制，不标为已完成贴身基础资产。默认不对通用角色强加白嫩肤质、美女身材或帅哥肌肉。快速横板的头部为0°/90°/180°/270°，分阶段头部为0°/45°/90°/180°，按实际路线验收角度。

## 查看真实图片

按原尺寸局部检查脸、手、衣物细节，再按模型实际可用的输入尺寸检查整板。大画布不保证缩小后五官可辨；面部近景和全身视图缺一不可。

1. 身份：头部各角度、半身、全身来自同一角色，五官、发际线、年龄感与体型没有漂移；确认后不重新融合原始参考人物。
2. 结构：0°、45°、90°、180°确为对应角度，AAA全身左右侧无镜像混淆；肩宽、四肢、手脚、全身比例可对应。
3. 造型：各视图服装、发型、配饰数量、左右位置、材质、穿法一致；没有基础服与新服装混杂。
4. 状态：修改仅发生于指定项；伤口、污渍、纹身等按自身左右和可见面出现，表情变化不改身份。
5. 画风：分别按写实、通用CG、AAA标准判断；皮肤、毛发、服装与附件的表现属于同一视觉体系。
6. 版面：头顶、脚底和必要外延配件完整，五官足够清楚；保留三张源图的完整内容、比例与内部视图布局，无多人场景或剧情首帧混入。

验收结论写“可用 / 局部可用 / 需修正 / 未核验”，明确可见证据和局限。用户确认与技术检查分别记录；没有用户确认不能写“已确认”。只做静态检查不证明视频生成的稳定性。

## 返修

服装与手脚问题使用[原有返修方法](review-and-repair.md)。生成结果的身份漂移、缺手、裁边等缺陷均先按原提示词、参考与参数重抽该源图，其他合格源图保持。不得因抽卡缺陷自行改脸、服装设计、提示词、规格或裁切。拼接算法有问题按已确认的三张整图连接方法修复，不把排版问题变成生图任务。

## 交付记录

沿用项目清单；没有格式时使用[简短示例](../assets/asset-record.example.json)。至少保留角色ID、基础/裂变类型、画风、服装与状态、适用剧情、来源版本、实际图片和源面板、提示词、参考职责、用户确认情况、验收结论及限制。字段只记录实际信息，不把样例当资产事实。

脚本的合成回执记录实际像素、裁切、面板框、缩放和源图摘要，辅助复现；它不是艺术或身份验收。分阶段拼接交付正式板时同时保留三张完整源图和拼接配置；快速生成没有独立面板或拼接配置时如实记录生成整板及提示词，不伪造中间文件。

交视频制作方时说明板中所有视角均为同一角色；不让参考板排版、白底、重复人物或示意标记进入视频。基础板够用时不补造型板；需要精确连续性时交对应造型/状态。具体镜头输入由R2V和导演选型，本技能不执行视频任务。
