# JSON Prompt System

## 已有明确摄影设计时

用户或上层 xhs-girl 已决定机位、构图、光线和成像时，先走[显式摄影入口](references/photography/README.md)。使用 `--photography` 和完整 `摄影设计` 卡，按真实规格传 `--resolution`。此分支读取摄影入口与摄影卡后直接拼装，旧生活照默认不参与。`--json-only` 保持纯 JSON，输出摄影卡。

未提供明确摄影设计时，沿用以下原有模式。

## 选择模式

资源根目录为 `references/json-prompt-system/`。明确指定的模式优先于参考图的镜头关系。用户要求时尚大片（fashion editorial）时使用专属模式。其余情况有图先看图，无图按文字判断拍摄者与人物的位置。

| 模式目录 | 使用条件 |
|---|---|
| mirror-selfie | 对镜自拍，画面取自镜中反射 |
| front-camera-selfie | 前置自拍，镜头位于人物前方、拍摄设备在画外 |
| third-person | 他拍，镜头来自外部拍摄者 |
| ecommerce-editorial | 时尚大片，按创意命题组织人物、空间、商品与视觉重点 |

## 生成动作卡

读取所选 `modes/<mode>/` 的 mode_rule.txt、mode_workflow.txt、mode_template.txt 与 mode_example.json，有 mode_quality_gate.txt 时一并检查。按模板生成合法 JSON 对象，示例仅用于校准。

- 三种生活照使用 soul.md、flowchart.md 和 core/ 的 rule.txt、Role.txt、workflow.txt；按动作和镜头需要补读对应专项规则。有参考图时分别锁定角色、服装、环境；缺图时按 rule.txt §12 补齐可见细节，已提供的人物档案作为身份依据。保留视角、裁切、重心、表情、手部接触，避免重复描述。
- 时尚大片直接走专属工作流，以“时尚大片”为根键。“画面内容”描述可见事件与空间关系；身份和服装按参考锁定。采用本模式的摄影策略和字段，不套用生活照的手机直出、缺图补写服装或动作卡结构。
- 卡片内不写路径、规则名、后台包装字段或过程说明。参考文件中的“输出纯 JSON”指动作卡阶段。

## 按任务编写参考图规则

完整输出时，先查看本次实际附带的全部参考图，再编写 `{{REFERENCE_RULES}}`。每张图按提交顺序标号，说明它负责的身份、体型、服装、妆发、场景、动作、构图或风格信息，以及应保留或调整的内容。单图可以承担多种职责，多图职责重叠时按用户指定优先级写清依据；无法可靠判断的关键冲突先向用户确认。

- 只给实际随本次生成提交的图片分配图号，保持提示词与工具上传顺序一致。
- 身份板、多视图板和场景板要说明用于参考，最终照片的数量、视角和排版按当前任务输出。
- 根据参考图和任务组织该段文字，不套用预设的模特图、服装图或道具图清单。未提供参考的角色、服装或场景由人物档案、任务设定和 JSON 中相应字段承担。
- 没有参考图时写“本次无参考图，依据人物档案、任务设定与下方 JSON 生成。”
- 该段与动作 JSON 的引用、人物档案及拍摄模式保持一致。

## 交付

1. 明确要求“只要 JSON”“仅动作卡”或等义要求时，仅返回动作卡 JSON，无代码围栏、固定提示词或说明。不需要画幅或人设即可交付；拼装脚本也支持 `--json-only`。
2. 其他情况默认读取所选目录的 fixed.md，沿用原文、标题和段落，将四个占位符一次性替换。可从 Skill 根目录运行 `python3 scripts/compose.py MODE --ratio 3:4 --profile-file 档案.md --reference-rules-file 参考规则.md < 动作卡.json`，将标准输出作为最终答复。也可按相同规则直接拼装。
   - `{{REFERENCE_RULES}}` 填按本次实际参考图编写的规则正文。使用脚本时通过 `--reference-rules-file` 传入 UTF-8 文件；无参考图可省略该参数。
   - `{{ACTION_JSON}}` 填本次动作卡，保留合法 JSON 和可读缩进。
   - `{{PROFILE_PROMPT}}` 原样填入用户交给 Agent 的人物档案（文字或指定文件），不预置人设。未提供时留空，不编造档案。
   - `{{RATIO}}` 使用用户指定的画幅或当前任务已确定的画幅，未指定时沿用网站默认 3:4。
3. 只交付拼好的正文一次，不额外重复动作卡。插入的参考图规则、人物档案与动作卡均作为原始内容，不再对其中的占位符做二次替换。
