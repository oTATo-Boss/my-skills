# 显式摄影设计入口

用于上层 Skill 或用户已经决定机位、构图、光线、妆造和成像的任务。拍摄关系仍从四种模式选择，完整卡由 `--photography` 启用。此入口只读取本页、photography/fixed.md 和当前摄影卡，旧生活照的 soul/core/mode 成像偏好不参与本次拼装。

根键 `摄影设计` 内的固定契约：

- `版本` 为字符串 `1.0`。
- `分享重点` 为具体可见的分享内容。
- `相机` 包含拍摄关系、摄影者位置、距离与透视、画幅边界四项字符串。拍摄关系为命令使用的模式名。
- `人物` 包含身份依据、妆发穿搭、姿态与支撑、视线与表情四项字符串。
- `空间层次`、`光线`、`明暗与颜色`、`成像质感` 为非空字符串。
- `成功条件` 为两三项非空字符串。
- `参考分工` 为数组，无图留空；每项包含整数图号、负责、保留、调整三个非空字符串。图号从1按实际上传顺序连续排列。

所有字段在卡内只能出现一次。填写完整的[本包例子](example.json)可直接运行。复制后替换人物与构图。xhs-girl 的 examples 另含多种完整拍法。

```bash
python3 scripts/compose.py third-person --photography --resolution 1K \
  --ratio 3:4 < references/photography/example.json
```

`--resolution auto` 默认写“按生成工具实际设置”，可指定1K、2K、4K。此文字不改变生成工具设置。工具执行者必须核实最终文件。`--json-only` 输出完整摄影卡，保持纯 JSON。`--profile-file` 可原样加入实际人物档案；档案与摄影卡需在提交前完成语义协调。

参考规则以卡内 `参考分工` 为唯一维护位置，摄影入口不接受单独的 `--reference-rules-file`。实际工具传图数量、顺序与卡一致。身份图保留身份，风格图保留摄影语言，服装图只在用户要求时锁定衣服。无法确认的关键身份冲突再提问。

脚本校验结构、字段类型、版本、模式、图号与成功条件数量。模型需另查身体支撑、前后关系和描述间语义冲突。旧命令与旧 JSON 模板继续按原模式输出，使用新入口时输入摄影卡，不把旧成像限制嵌回其中。
