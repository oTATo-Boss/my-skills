json-prompt-system Core Rule

1. 文件定位
- 当前体系是多模式动作变量层系统，不绑定单一拍摄模式。
- `core` 负责跨模式通用规则；`modes` 负责各拍摄模式的专属补丁。
- 这份 JSON 只负责动作、体态、镜头关系、表情、拍摄逻辑、构图重点、支撑关系、衣物边界关系和手机直出质感。
- 有参考图时，不负责模特身份、人物外形、服装款式、颜色、材质、图案或配饰；无参考图时，必须由本 JSON 补足角色、服装与环境（见 §12），否则成图没有依据。
- 若某个 mode 明确允许场景、光线、空间或环境互动，只能服务照片成立和动作可信度。

2. 产品域边界
- 只处理日常社媒照片语境下的中性动作变量。
- 只输出中性照片动作变量。
- 用户提出不属于动作变量层的意图时，只保留可执行的构图重点、遮挡关系、衣物边界、姿态、表情和镜头距离；不属于动作变量层的目标不写入 JSON。
- 输出只保留可执行的中性照片变量；不属于动作变量层的请求不进入 JSON。

3. 输出规则
- 统一使用纯 JSON。
- 默认从当前 mode 的模板结构开始组织内容，不随意增删主结构。
- 全中文表达，短句、参数化、结构化。
- 生活图 mode 必须压缩输出但不丢细节：保留视图构图、主动作母题、表情强度、身体/坐姿结构、衣物边界或手部牵引。
- 最终 JSON 不得出现文件路径、规则名、开发说明、读取过程、引用来源或不可执行元信息。

4. 模式路由
- 任何任务开始前，必须先参考 `core/mode_selector.txt` 选择 mode。
- locked mode / modeHint 最高优先级，高于图片识别、用户文本和历史上下文。
- 只有 `AUTO` 允许在 `mirror-selfie`、`front-camera-selfie`、`third-person` 之间自主判断。
- `ecommerce-editorial` 在明确指定时尚大片时启用，不参与动作库 AUTO 判断。
- 非 `AUTO` 不允许切换 mode，不允许输出其他 mode 的模板结构、术语或拍摄逻辑。

5. 身体与物理规则
- 姿势必须符合真实骨骼、关节和重心逻辑。
- 抬手、拢发、回头、交叉腿、撑扶、整理边界等动作都要写清身体连锁变化。
- 肩线、颈部、上身结构、腰线、骨盆、腿部之间要有连贯逻辑。
- 不能出现自拍逻辑或视角逻辑互相冲突的结构错误。

6. 衣物边界规则
- 有服装参考图时，只写边界、遮挡、接触点、牵引方向、裁切关系和动作带来的轻微受力；具体款式、颜色、材质、图案、配饰、品牌交给参考图，不重述。
- 无参考图时，服装必须在 `角色与服装` 的服装块里写清：上装、下装、鞋袜、配饰、版型与材质、颜色、穿着状态；动作字段里仍按边界关系写，不重复整段款式描述。
- 无论有无参考图，都不把服装信息写进表情、焦点区域、头部状态、视觉关键词或色彩字段。
- 对不属于动作变量层的目标，保留中性的边界接触和构图关系，不写入目标本身。

7. 手机真实感
- 全 mode 禁止要求或暗示背景虚化、浅景深人像焦外、大光圈奶油虚化、bokeh、人像模式级背景糊化等单反/人像镜头审美。
- 全 mode 禁止专业摄影式后期：分区调色、HDR 光效、强风格调色、电影式分层、抠像感、刻意把背景修成干净板。
- 可用极轻措辞锚定真实生活直出：轻微颗粒、社交压缩后的直出、轻锐化、小传感器弱光下的一点颗粒感。
- `mirror-selfie` 与固定场景参考图对接时仍不写具体背景、环境、灯光。

8. 女性社媒呈现
- 可写自我检查、发布意图、角度确认、松弛但有控制、不对称微误差、表情停顿、镜头意识。
- 吸引力只按构图吸引力、形象表达、视觉重点和照片生命力处理，不写成不属于动作变量层的吸引。
- 表达强度通过重心、肩胯、眼神、嘴部、手部停点、非对称构图、动作缓冲、衣物边界关系和裁切组织。

9. 以图还原
- 用户提供图片时，默认允许做动作变量层还原。
- 优先提取拍摄方式、手部逻辑、身体朝向、承重关系、头部方向、表情、眼神、动作与衣物边界物理逻辑。
- 有参考图时舍弃人物长相、服装款式、背景环境、光线氛围、颜色和品牌信息，只保留一致性要求；无参考图时不得舍弃，按 §12 写全。

10. 创作检查
- 是否先完成 mode 选择。
- 是否使用当前 mode 的模板主结构，未混用其他 mode 字段。
- 是否只有两只手，且左右手逻辑成立。
- 是否有明确承重关系、支撑点和动作连锁。
- 是否动作、表情、情绪一致。
- 是否只写中性衣物边界关系，没有越界到服装细节或不属于动作变量层的目标。
- 是否按输入判断了角色、服装、环境三块：有参考图只写一致性，无参考图写全且不留空。
- 角色、服装、环境是否与动作、构图、光线一致。
- 是否未写单反焦外、bokeh、HDR 光效、强风格调色或专业后期。
- 是否清除文件路径、规则名、开发说明和不可执行元信息。

12. 角色、服装与环境（无参考图时的补足）
- 三种输入分别判断：人物、服装、场景。每一块独立决定"以参考图为准"还是"文内写全"。
- 有对应参考图：`来源` 写参考图编号，角色块只写一致性要求，服装块只写边界与贴合，环境块只写空间关系与光向，不重述参考图里已有的细节。
- 无对应参考图：必须写全，字段不能留空。
  - 角色：persona 锚点、年龄段感、体型与骨架、发型状态、气质与表情基调。只写可执行的可见信息，不写具体姓名、真实人物或品牌。
  - 服装：上装、下装、鞋袜、配饰、版型与材质、颜色、穿着状态。写"她此刻穿成这样"，不写商品名与营销词。
  - 环境：场景类型、空间与陈设、生活痕迹、光源与时点、环境色与明暗、空间合理性。环境必须能解释光线和支撑关系。
- 三块内容必须和动作、构图、光线一致；冲突时以动作与拍摄方式为准，回头改这三块，不要硬塞。
- 角色与服装正文只出现在这两块里，动作字段仍然只写边界、牵引、遮挡和受力。
- 时尚大片使用专属字段和身份保护规则。

13. 文件定位补充
- 本 JSON 是完整提示词的一个组成部分，不承担网站端 MD 提示词、参考图编排或后端逻辑；只补齐让 JSON 能独立成立所需的最小信息。

11. 参考文件优先级
- 先参考 `core/rule.txt`、`core/pipeline_context.txt`、`core/detail_control_logic.txt`、`core/workflow.txt`、`core/mode_selector.txt`。
- 生活图 mode 再参考 `core/women_selfie_presentation_logic.txt`、`core/visual_anchor_abstraction.txt`、`core/expression_intensity_logic.txt`、`core/original_pose_invention_logic.txt`、`core/anatomy_pose_sanity.txt`、`core/expressive_pose_translation.txt`、`core/seated_pose_anatomy_library.txt`、`core/output_density_control.txt`。
- 表达强度任务可参考 `core/expressive_pose_examples.txt` 与 `core/bad_cases.txt`。
- 图片还原任务加读 `core/image_restore_checklist.txt`。
- 最终输出必须基于对应 mode 的 `mode_rule.txt`、`mode_workflow.txt`、`mode_example.json`、`mode_template.txt` 和 `mode_quality_gate.txt`。
