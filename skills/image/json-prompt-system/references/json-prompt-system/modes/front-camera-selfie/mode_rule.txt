front-camera-selfie Mode Rule

1. 模式定位
- 本 mode 只处理前置自拍或人物面对前方屏幕的自拍任务。
- 重点不是镜面关系，而是画外前置视角、屏幕意识、手臂延伸、近距离构图，以及真实前置自拍中的场景氛围成立性。
- 与 mirror-selfie 不同，本 mode 允许写场景还原、光线氛围、人物与环境互动，但这些内容必须服务于“真实前置自拍成立”，不能写成空泛审美描述。
- 本 mode 必须参考 `core/front_selfie_screen_logic.txt`：前置自拍的灵魂是屏幕意识、自我确认感、近距离亲密感、画外前置视角和真实生活支撑。

2. 核心成立条件
- 前置取景不依赖镜子成立。
- 默认写“画外前置视角”，不默认写可见取景实体。
- 默认必须让前置自拍的画外视角逻辑成立：可以是手臂前伸、定时自拍、支撑视角或近距离前方视角。
- 如果参考图里的双手都参与姿势，不要强行改出持机手；把近拍侧手写成“无可见持机手，定时自拍或画外前置视角成立”，再写清双手各自的动作停点。
- 默认构图应更近，优先近景、胸像、半身，不优先远距离。
- 默认人物应直接面对屏幕或轻微迎向前方视角，不应像第三视角站拍。
- 默认画面应具备生活场景或自拍场景依托，不能只有悬空人物和空白背景。
- 默认必须存在至少一个明确的主支撑点，让人物不是悬空姿态。
- 默认结果必须像真实会保留的自拍成片，而不是动作示意图。

3. 前置自拍专属关注点
- 画外前置视角是否明确
- 是否只通过屏幕意识、手臂透视、定时自拍或近距离前方视角成立
- 手臂前伸、定时自拍、支撑视角或近距离前方视角至少一种成立
- 画面距离是否足够近
- 面部是否在和屏幕画面形成直接关系
- 表情是否自然，不僵硬、不空、不呆
- 场景、光线、支撑面是否帮助前置自拍成立
- 是否具备自然美照感，而不只是动作正确

4. 默认约束
- 若用户未特别要求，只写画外前置视角，不写任何可见取景实体。
- 若用户未特别要求，构图优先胸像特写、近景半身或中近景，不写远距离全身前置自拍。
- 若用户未特别要求，画外前置视角位置优先：
- 略高于眼平
- 眼平附近
- 不默认低角度远举
- 若用户未特别要求，表情优先：
- 自然放松
- 轻微专注
- 微弱互动感
- 不写强表演感
- 若用户未特别要求，允许补充：
- 场景还原
- 光线氛围
- 人物与环境互动
- 但必须和动作、取景关系、构图距离一致

5. 常见失败方向与修正
- 失败方向：画面出现取景实体
- 修正：明确写“画外前置视角，仅通过手臂延伸、近距离透视或人物迎向屏幕关系体现前置自拍”

- 失败方向：构图太远，不像前置自拍
- 修正：明确写“近距离胸像特写、中近景半身、前方视角贴近人物”

- 失败方向：人物太刻板、太像摆拍
- 修正：增加头部小偏转、手指轻停、眼神落在屏幕附近、动作未完全停稳的缓冲感

- 失败方向：表情呆滞
- 修正：眼神写成“半聚焦、看屏幕画面、轻回落”，嘴部写成“自然微张或轻松放松”，不要只写“直视镜头”

- 失败方向：场景单一，没有生活氛围
- 修正：补充支撑面、倚靠关系、局部光线方向、人物与场景接触点，让画面像真实女生自拍而不是悬空人像

- 失败方向：中距离构图不成立
- 修正：让至少一个近处身体部位进入前景关系，如膝部、手臂、抱物边缘、靠近镜头的肩线，不要写成远距离直立站拍

- 失败方向：空间逻辑不成立
- 修正：明确谁在承担主要重量，头部、肩线、手臂、身体分别压在哪个支撑点上；装饰性手势不能替代主支撑点

- 失败方向：画面像动作示意，不像美照
- 修正：补充自然的光线氛围、生活场景依托、表情微变化、非对称小偏差和会被保留下来的自拍感

6. 局部细节使用规则
- `局部细节` 用来容纳前置自拍中常见的近距离特征。
- 可以写：
- 发丝与面部的接触关系
- 嘴角、下颌、脸侧边缘的局部状态
- 手指与发丝、脸侧、下巴边缘的停留关系
- 其他局部结构细节
- 不写：
- 皮肤材质
- 妆容
- 服装款式
- 具体服装款式、人物外形或皮肤材质
- 可写锁骨、上身与上方边界附近的动作与可见范围、上身轮廓线条等，但必须落到前置距离、角度、衣物边界牵引和裁切关系。

7. 画面氛围控制使用规则
- `画面氛围控制` 是 front-camera-selfie 的专属扩展层。
- 可以写：
- 场景还原，如人物所处的生活场景类型、支撑面关系、自拍时的空间氛围
- 光线氛围，如柔和日常光、贴近画外前置视角侧的亮面、夜间室内弱光、晨间窗边感
- 人物与环境互动，如靠枕、侧躺、倚靠、抱膝、贴近床面、靠近桌边、靠墙
- 氛围关键词，如可爱、懒散、安静、睡前感、清晨感、窝着自拍
- 不可以写：
- 复杂摄影术语堆砌
- 和动作无关的纯审美描述
- 与参考图强冲突的具体硬设定
- 明显带刺激导向的环境描述

8. 空间成立控制使用规则
- `空间成立控制` 用来锁定前置自拍里的真实空间关系。
- 必须写清：
- 主支撑点：人物主要重量落在哪里
- 辅助接触点：手、肩、头、腿等部位和环境的次级接触
- 前景关系：中距离自拍里哪一个部位靠近镜头形成前景
- 空间合理性：为什么这张图像是前置自拍而不是第三视角摆拍
- 特别规则：
- 装饰性托脸手、扶脸手、拨发手，默认不是主支撑点，除非明确指定
- 躺姿、侧躺、窝坐、抱膝、靠姿，都必须先有支撑面，再谈动作细节
- 中距离前置自拍必须有前景部位或明显手臂透视，不能只有平铺直叙的人体
- 如果动作来自上传参考图，优先保留参考图的主姿势、裁切和构图比例，再把拍摄来源翻译成画外前置画外前置视角；不得因为原图不像手持自拍就自动放弃或切成他拍。

8.1 景深、背景与画面处理（全 mode 一致）
- 不得在 JSON 中写背景虚化、浅景深、bokeh、人像焦外等；不得写对背景或画面的专业摄影式后期（分区调色、HDR 分层、抠像感等）。前置自拍按**普通人生活随拍**理解，用近距离、机位与构图表达主次。
- **可选用**：在 `拍摄参数` 或 `整体视觉目的` 等与成片气质相关的槽位，**极轻**点一句轻微噪点/细腻颗粒/略像压缩直出，一两短句，见 `core/rule.txt` §9。

9. 自然美照标准
- 目标不是只生成“正确的自拍动作”，而是生成“真实自然、氛围成立、人物好看、像真实女生自拍”的图片提示词。
- 默认审美方向：
- 自然
- 真实
- 松弛
- 好看
- 有生活感
- 有自拍保留价值
- 禁止把人物写成：
- 僵硬示范姿势
- 空洞表情
- 没有支撑关系的悬空人物
- 没有环境依托的纯动作图

9.1 女性自拍呈现还原
- 本 mode 必须参考 `core/women_selfie_presentation_logic.txt`。
- 同时参考 `core/front_selfie_screen_logic.txt`、`core/visual_anchor_abstraction.txt`、`core/expression_intensity_logic.txt`、`core/original_pose_invention_logic.txt`、`core/anatomy_pose_sanity.txt`、`core/expressive_pose_translation.txt`、`core/seated_pose_anatomy_library.txt`、`core/output_density_control.txt`。
- 前置自拍要优先读懂近距离脸部气质、表情动作和屏幕意识：她是冷淡、慵懒、娇俏、自信、清冷，还是漫不经心。
- 近距离视图里的魅力经常来自脸部表情和肩颈/上身/腰线的取舍，不是每次都靠大动作。
- 微表情必须具体写眼睑、视线、嘴角、唇部、下巴、头部角度；不能只写“刚看到屏幕里自己不错”。
- 屏幕意识必须具体：视线落在屏幕里的自己、镜头旁一点、屏幕下沿或略偏离镜头；嘴角、唇部、下巴和头偏角要像正在确认这个角度。
- 曲线和展示目的要顺着当前构图：近景可强调脸、肩颈、上身轮廓；中近景可补腰线、髋线或腿部前景；不得硬改成远距离全身动作。
- 以图还原时，必须尽量完美还原原图里女性的气质、拍照情绪、目的、身体曲线和微表情，而不是泛化成一个普通前置自拍。

9.2 服饰中立、表情强度、原创动作与人体检查
- 有图还原时，不得把任何具体服装、穿戴、配饰、颜色、材质、图案、品牌或道具款式写进最终 JSON；只能写上方边界、衣物边界、腰线边界、腿部边界、遮挡关系和边界牵引等动作变量。
- 服装/配饰信息不得出现在表情、焦点区域、头部状态、视觉关键词或色彩氛围字段；前置自拍只写画外画外前置视角、裁切、屏幕意识、表情和边界互动。
- 表情必须选择清晰强度档位：克制、轻松镜头感、甜/娇俏、自信强表达；并落到眼睑、视线、嘴部、下巴/头部角度，不得只写“冷淡、有镜头表现力、可爱”。
- 无图原创必须根据用户意图选一个主动作母题，不能只写近距离看屏；可选靠近画外前置视角低头看屏、托脸停住、拨发停住、抱膝靠近、侧躺抬眼、手指停在下巴边等。
- 前置自拍不引入镜面规则；重点检查画外前置视角、手臂前伸路径、主支撑点、手腕和手指停留方式是否真实可执行。
- 如果画面使用固定画外前置视角或定时自拍，不要求出现手臂前伸路径；重点改为画外前置视角画外位置、人物迎向画外前置视角的视线、支撑面和近距离透视是否成立。
- 当前置自拍遇到完整坐姿，尤其 M 字鸭子坐时，默认近景规则失效；必须拉远为中全身或全身坐姿构图，让腰部、骨盆、双膝和小腿折向进入画面。
- 用户明确要求整理边界/牵引/突出上身轮廓时，服饰中立化不能削弱动作；必须写非持机手两指钩住上方衣物边界向边界方向轻整理，边界位置被整理得更清楚，上身中心线/上身轮廓线条可见。
- 复杂动作优先级固定为：先锁 M 字下盘，再写上半身前倾，再写边界边界整理，再写 wink/咬舌/微笑；不得先按近景脸部自拍裁切。
- 最终 JSON 必须按输出密度控制压缩：每个字段只写自己的职责，用短锚点保留视图构图、主动作母题、表情强度、身体/坐姿结构、衣物边界或手部牵引；不得用长段复述替代动作细节。

10. 写法风格要求（叙事触发优先）
- 表情控制、画面氛围控制、心理暗示、整体视觉目的中的文字描述，必须优先使用叙事触发式写法。
- 叙事触发 = 写一个 2 秒内的微故事或瞬间，让模型自己去“拍”这个瞬间。

好写法示例：
- 眼神：“像在前置屏幕里看到了一个不错的自己——还在确认，但已经有点小开心了”
- 嘴部：“像刚轻轻哼完一句歌，嘴角还带着没散掉的弧度”
- 氛围：“cozy, intimate, soft, 像睡前发给喜欢的人的那种自拍”
- 心理：“她不是在拍照，她是在确认自己窝在这里是不是很可爱——确认完了，是的”

坏写法示例（禁止）：
- “面部状态：轻松、柔和、带一点窝着自拍的可爱感”（这是第三方总结，不是瞬间叙事）
- “情绪浓度：中低强度”（模型无法执行“中低强度”）
- “氛围关键词：窝着自拍、放松、可爱、安静、生活感”（标签堆砌，不是情绪锚点）

详细规则见 `core/detail_control_logic.txt` 八.

11. 动作边界
- 前置自拍中的表达强度依旧只能通过参数实现：
- 画外前置视角位置
- 近距离构图
- 眼神停顿
- 嘴部微张或轻抿
- 手指轻触
- 发丝与脸侧关系
- 头部微偏
- 场景中的倚靠、贴近、抱膝、侧躺、靠枕等生活化互动
- 不通过空泛词替代动作；张力必须落到视线、嘴部、手部停点、身体角度、裁切和衣物边界
