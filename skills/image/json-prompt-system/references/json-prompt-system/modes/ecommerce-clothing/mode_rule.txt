ecommerce-clothing Mode Rule

1. 模式定位
- 本 mode 只服务“效果库”的服装渲染效果。
- 目标是生成高保真的电商服装渲染 JSON，不是模特上身图，不是真人商拍，不是生活照，也不是情绪海报。
- 最终图像类型是 Ghost Mannequin / 3D 商品图 / 工艺细节图 / 功能展示图。

2. 总写法
- 必须保持结构稳定、字段直接、结论唯一。
- 必须像现有效果库里的商品渲染协议，而不是短卡摘要。
- 优先写“模型必须保留什么、必须怎么渲染、绝对不能错什么”。
- 禁止写品牌文案、情绪散文、导演阐述、广告口号。

3. 输出骨架
- 顶层固定为五段：
- 版本标记
- 任务定义
- 视觉提示
- 技术规格
- 负面限制
- 不允许改成其他顶层结构。

4. 任务定义规则
- 任务定义必须只包含：
- 角色
- 目标
- 输入保真要求
- 角色默认是“电商服装摄影与商品渲染专家”。
- 目标必须明确当前是主视角、局部特写或功能展示中的哪一种。
- 输入保真要求必须强调：外观信息由参考图锁定并原样承担；JSON 不复述颜色、纹理、印花、图案、材质或辅料名称，只写结构、边界、开口、厚度、受力和工艺逻辑关系。

5. 视觉提示规则
- 视觉提示必须只包含：
- 主体结构
- 细节保留
- 环境
- 主体结构负责定义当前渲染视角、立体成立方式、开口深度、边缘厚度、褶皱受力和局部结构重点。
- 细节保留必须明确参考来源和必须保住的关键关系；不得列出具体颜色、材质、图案、款式或辅料名称。
- 环境默认是纯白无缝背景 + 商业棚拍柔光，不允许写花哨背景。

6. 主视角规则
- 正面 / 反面 / 侧面 / 45 度立体都必须强调：
- 服装像被无形人体自然撑起
- 轮廓有体积，不是纸片
- 开口、袖筒、衣身厚度、肩线和下摆必须成立
- 只能允许内部结构阴影，不允许地影、墙影、投影或悬浮感
- 45 度视角必须特别限制透视错误、前后片混乱和上方开口结构失真。

7. 局部特写规则
- 局部特写必须优先：
- 放大局部结构
- 明确工艺关系
- 明确参考图锁定的表面关系
- 明确边缘厚度、缝合、贴合或开合逻辑
- 禁止把工艺特写渲染成贴图、平面印刷或错误结构。

8. 功能展示规则
- 厚薄感、内里夹层、口袋与开合结构都属于“功能展示”。
- 必须强调结构逻辑，而不是美感氛围。
- 必须让用户一眼理解层次关系、厚度关系、开口深度或功能成立方式。
- 禁止只写“高级”“质感好”，必须写清楚具体结构成立点。

9. 环境与光线规则
- 环境默认回答三件事：
- 背景是什么
- 光线是什么
- 阴影允许到什么程度
- 默认使用纯白无缝背景。
- 默认使用商业棚拍柔光或软定向光。
- 阴影只允许帮助展示内部深度、褶皱、边缘厚度和局部结构。
- 不允许真实地影、墙影、戏剧投影、脏背景、灰底脏光。

10. 技术规格规则
- 技术规格必须只包含：
- 分辨率
- 清晰度
- 输出风格
- 默认写高分辨率、高锐度、写实商品渲染。
- 禁止写电影感、胶片叙事、海报感等偏离商品图的词。

11. 负面限制规则
- 负面限制必须集中压制四类错误：
- 真人写入：人物、皮肤、手、脖子、四肢、支架
- 假模特感：塑料假人、塑料光泽、错误表面感、支撑杆
- 贴图感：平面边缘、假缝线、贴纸感、错误工艺
- 电商不可用：模糊、噪点、脏背景、错误透视、错误阴影、参考外观漂移
- 每条都必须结合当前任务类型写出最相关的限制。

12. 单值规则
- 所有字段都必须给唯一答案。
- 禁止出现：
- 或
- 可
- 可选
- A/B
- 也可以
- 根据情况
- 信息不足时也要补成最稳的商业结论。

13. 最终标准
- 读完这份 JSON，模型必须立刻知道：
- 这张商品图是主视角、局部特写还是功能展示
- 服装结构要怎么成立
- 哪些细节必须保真
- 哪些错误绝对不能出现
- 成品必须像可以直接用于电商详情页的商品渲染指令，而不是概念稿。
