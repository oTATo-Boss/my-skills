# Midjourney 执行专家

理解用户目标，选择 MJ 功能，组合必要操作，完成交付。决策由本 Skill 指导 Agent 完成；`scripts/mj.py` 负责可靠执行，不包含自动视觉评分或提示词创作模型。接口是第三方 Apilio 的 Discord 代理协议，不等同于 Midjourney 官方 API，也不保证支持 MJ 官网的所有新功能。

## 先形成最小执行计划

从会话提取：新建还是已有任务、参考图用途、目标尺寸/比例、数量、交付形式、模式与额外操作范围。沿用已有授权及配置；只在缺少必要素材、凭据、已有任务 ID 或实质影响结果的选择时提问。用户只要分析或提示词时不提交任务。

本机统一配置默认读取 `~/.config/apilio/credentials.json`（权限 0600，字段 base_url、api_key，MJ 专用路由可用 mj_base_url）；用户已确认基础地址为 `https://api.apilio.ai`。优先级：显式 --base-url > MJ_BASE_URL / MJ_API_KEY > APILIO_BASE_URL / APILIO_API_KEY > 私有配置。Base 是 `/mj` 之前的地址，可带模式前缀。不要把密钥写进 Skill、命令行、仓库或交付物。模式、路由、返回码及字段读 [references/apilio-api.md](references/apilio-api.md)；脚本命令读 [references/execution.md](references/execution.md)。

在付费提交前确定本轮最短操作链与 POST 上限（执行器 `--max-posts`，同一工作流共用 `--state-dir`）。按任务已有授权推进；默认不额外探索。已有偏好优先，否则沿用令牌默认模式，不擅自升级 turbo。一次生成并提取最佳单图通常 2 次提交；需要 modal 则计入额外一次；四张单独提取通常 5 次。计数是防失控措施，不代表金额预算，也不意味着每次同价。实际价格以该账号平台报价为准，查询虽标免费也应合理轮询。

## 任务识别与路由

| 用户意图 | 路径 | 判断要点 |
|---|---|---|
| 从零生图 | imagine | 已写好的最终 prompt 直接提交 |
| 用参考图生成新内容 | imagine + 图像输入/参考参数 | 普通 image prompt、风格参考、身份参考先区分；不是混图，也无需先 describe |
| 多张图融合 | blend | 目标是多图视觉混合；若要文字明确控制主体或构图，优先 imagine + 多参考 |
| 分析图片、反推描述 | describe | 交付文字；不顺手再生图 |
| 精简/分析现成 MJ prompt | shorten | MJ 自身分析，不替代外部 Prompt Skill |
| 选四宫格中的一张 | action → 对应 U1–U4 | 选择、单图提取与高清增强的含义依模型和返回按钮确认 |
| 基于结果做变体 | action → V1–V4 / Vary | 只选择当前任务实际支持的操作 |
| 更高清 | action → 实际 Upscale 按钮 | 如已有单图仍需增强，再检查返回的增强按钮及预算 |
| 重抽、扩图、平移构图 | action → Reroll / Zoom / Pan | 构图目标明确后选择最少动作；有些会进入 modal |
| 改已有 MJ 图的局部 | action → Region → modal | 先取得弹窗任务 ID，再提交编辑 prompt 和蒙版 |
| 编辑外部图片 | edits | 直接传 image URL、prompt、maskBase64；不先生成一张 MJ 图 |
| 恢复断连/进度查询 | fetch / wait | 优先恢复原 ID，不能因为超时就重提交 |

Action 的 `customId` 必须来自刚查询的 `buttons`；按 label/emoji/语义判断，歧义时用返回的精确 ID。不得拼造 ID、固定模板或假定每种任务都有 U/V/Zoom。先查询成功父任务再 action；每个子任务也要独立等到完成。

## Prompt Skill 协作

需要创作/修改提示词时，按当前技能索引找到 `midjourney-prompting`（本机一般为相邻的 `../midjourney-prompting/SKILL.md`），只读取相关参数或参考资料。明确交接：用户目标、参考图角色、已确认模型能力、比例与不可改变项；拿回 **API 可直接提交的最终 prompt、参考 URL/类型、版本参数**。传入 `prompt` 时移除 Discord `/imagine` 命令包装，不擅自改写审美表达。

已经有最终 prompt 时直接复用；缺少 Prompt Skill 且用户只给概念时说明缺少提示词创作依赖，保留可执行计划，不能谎称已调用。它的版本/参数建议也需与该代理实际能力交叉检查，不把官网或 Prompt Skill 的新版本表当作代理已支持的证据。已有明确版本沿用；未知则沿用账号默认，不凭空强加版本。

“同风格时尚大片”属于新生成 + 风格参考；必要时先上传本地图取得 URL，由 Prompt Skill 安排 `--sref` 等参考语法。普通 `base64Array` 垫图不能自动视为风格锁定；身份参考也不能自动等同于普通垫图。不要为了参考风格额外调用 describe。

## 状态、弹窗与恢复

- `code=1/22` 仅说明任务已接受/排队，立即持久化 ID；只把 `status=SUCCESS` 当作执行完成。`progress=100%`、有 `imageUrl` 或 HTTP 200 都不足以证明成功。
- `code=21` 保存 **此次响应 result 的新 ID**，进入 modal；`status=MODAL` 也需处理。不要在旧父 ID 上直接重绘。Region 用与目标图对齐的 PNG 蒙版：黑保留、白编辑。Custom Zoom 的最终 prompt 需合法 `--zoom`；Remix 弹窗按用户修改目标确认最终 prompt。
- `FAILURE`、`CANCEL` 立即停止，保留 `failReason` 和完整快照，不自动重抽；`MODAL` 停止纯轮询并转入二次提交。未知状态保留快照并有界等待，不直接判失败。
- 网络/轮询超时后恢复 GET 原 ID。POST 发出但响应丢失、没有 ID 时，把操作记为结果未知，查平台任务历史/账单后恢复；不能自动再 POST、换路由重试或换操作名绕过保护。
- 每次 mutation 使用稳定 `--op`（如 `initial`、`extract-2`、`region-modal`）。同键同输入复用保存结果，不重复提交；相同输入需要用户意图明确的第二次重抽时才新建操作键。不要删除状态目录重置预算。

## 验收与停止

1. 生图完成后下载预览并用视觉工具实际查看。四宫格按左上/右上/左下/右下对应 1/2/3/4，先确认真实布局；按用户目标比较主体、构图、质感、参考一致性、明显结构错误。记录简短选择依据；无法看图时不能声称选出最佳，用户没指定序号则说明视觉能力限制。
2. 用户要“最佳一张”时选出一张，执行该张真实 U 操作，检查返回是否已是独立图；只有分辨率仍不达要求且在范围内时继续高清增强。用户只要四宫格时直接交付，不自动放大。
3. “四张独立图”默认按返回 U1–U4 分别提取并查询子任务。用户明确只需从网格拆出文件、接受原像素时可以本地裁切，但必须标注裁切；不能把裁切称为 MJ Upscale，也不能把 U 操作一律宣传为提高像素的放大。
4. 编辑结果检查目标区域是否达到要求、主体及保留区域是否合理保持；Describe/Shorten 检查并交付文字结果，不要求 imageUrl。
5. 图片下载后验证可完整解码、实际格式、像素尺寸、文件大小和哈希。执行器下载依赖 Pillow，缺失时使用现有具备 Pillow 的 Python；不能只有链接/HTTP 200 就声称文件验证通过。蒙版几何与内容由 Agent 结合参考检查，脚本不代替视觉检查。
6. 交付可点击本地图片/文本结果，简述尺寸、选图或编辑结论、是否裁切，以及实际任务 ID、执行模式（若可确认）和追加操作数。保留父子任务链及原始结果在私有状态目录，不把 base64、凭据或全部调试 JSON 填进回复。

达到用户交付标准即停止。未满足时先定位问题，再在授权范围内做有针对性的最少动作；不要把“最佳”理解为无限变体/重抽。额度耗尽、功能缺失或失败时交付已有有效结果、可恢复 ID 及真实限制。
