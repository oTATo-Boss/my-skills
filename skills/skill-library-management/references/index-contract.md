# 索引契约与模板

## 层级和维护源

总索引只维护分类路由；分类索引维护本层技能清单。真实嵌套包由包内索引维护子技能。大型示例库可以使用 `catalog.md`、结构化目录和来源清单，不要求把每个示例计成 Skill。

每个包含共享技能的分类文件夹都有 `SKILLS_INDEX.md`。下一层目录只有存在独立清单或明显检索需求时才增加索引，不给每个脚本／素材子目录制造空目录文件。

一个 Skill 在库内的拥有清单中登记一次。返回父目录、跨分类参考与项目选型可以链接它们，但不形成第二份完整维护清单。分类数量是本分类递归拥有的 Skill 数，示例／素材数单独标注。

## 格式

使用以下行式登记；目录名、Skill 名和文件路径无需相同，入口以真实 `SKILL.md` 为准：

```markdown
# 分类技能索引

技能数量：2

[返回总入口](../../SKILLS_INDEX.md)

## 什么时候查本分类

一句话说明目标产物和典型任务。

## 相关主题

- [example-skill](example-skill/SKILL.md) — 一句话用途。
- [nested-pack](nested-pack/SKILLS_INDEX.md) — 何时进入子包目录。
```

`技能数量：N` 统计本索引直接登记的 Skill 与通过导航行递归拥有的子包技能。目录文件只用于组织信息，不把目录文件本身算成 Skill。

总入口同样使用导航行：

```markdown
# Skill 库总入口

技能数量：12

先按目标选分类，再读分类索引和需要的 Skill／资源目录。

- [animation](skills/animation/SKILLS_INDEX.md) — 动效编排、交互和示例改编。
- [threejs](skills/threejs/SKILLS_INDEX.md) — 浏览器三维场景、材质、渲染和交互。
```

共享给多个客户端的机器本地索引可以采用稳定绝对路径；随仓库或 Skill 分发的索引优先使用相对路径。路径含空格时用 Markdown 的 `<...>` 包裹目标。返回父级链接写成普通段落，拥有下一层清单的链接写成上面的导航行，避免将返回导航误作清单依赖。

## 主题分组

分组回答“当前任务从哪里进入”。例如 Three.js 分类可分项目集成、场景镜头、几何材质、运动特效、自然环境、渲染和质量；Anime.js 可分 API、框架工作流、创意和示例。

沿用现有分类与实际用途。不要用历史使用次数、作者、来源站点或文件数量替代任务选型，也不为追求对称而复制技能到多个文件夹。

## 项目索引

项目清单只包含该项目实际有用的入口与用途，可以补版本、选用理由和限制。项目规则说明其用途与维护时机；它引用共享维护源而不接管系统／插件文件。
