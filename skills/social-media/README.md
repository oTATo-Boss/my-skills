# Social Media

一套可移植的社交内容工作方法：五个独立技能、一个轻量路由和一份可选项目配置。适用于不同创作者、品牌、题材和平台，不含任何项目资产、账号、凭据或固定生成服务。

## 技能分工

| 技能目录 | 做什么 | 主要交付 |
|---|---|---|
| `content-planning` | 参考研究、创意选择、脚本分镜、素材需求 | 可执行创作简报 |
| `asset-generation` | 身份与资产整理、缺失图片、生成提示词与视频素材、源素材验收 | 已核实素材与生成记录，或明确未执行的方案 |
| `content-production` | 剪辑、声音、完整成片验收、封面 | 成片、封面及实质限制 |
| `publishing-delivery` | 标题、正文、标签、逐篇整理文件夹 | 待发布素材文件夹；不自动发布 |
| `performance-analysis` | 后台数据采集、同口径比较、改进建议 | 有证据边界的表现分析与可检验实验 |
| `social-media-router` | 识别请求阶段、按需串联以上技能 | 最短必要工作路径 |

数据技能不浏览或复盘用户点过赞、收藏过的内容列表；已授权后台导出中的聚合点赞数、收藏数可作为可选表现指标，除非当前任务也排除这些指标。

## 使用与发现

交付物是这个普通文件夹。若传输渠道使用 ZIP，解压即可；ZIP 只是运输方式，不是技能格式，也不规定以后作品的交付格式。本套件没有伪装成通用多技能 `.skill` 安装包。

不同宿主的技能发现规则不同。不要假定把外层 `Social Media/` 丢进某个目录后，宿主一定会递归发现其下六个技能。按目标宿主当前文档，把需要的各个内层技能文件夹分别放入其技能发现目录，或逐一登记路径。文件夹名必须与其 `SKILL.md` 的 `name` 保持一致。此套件本身不执行安装。

- 单独使用：只复制一个技能的完整文件夹，连同其中 `references/`。各技能的必要说明均在自己的目录内，没有必需的兄弟目录依赖
- 组合使用：让宿主能找到需要的内层技能，再使用 `social-media-router`。路由器不会假定同级技能已经安装；找不到时给出该阶段的输入/输出要求，不声称已调用
- 项目配置：将 [共享模板](shared/project-config.template.yaml) 复制到项目目录，填写后通过请求提供路径。配置是可选数据，不是安装依赖或操作授权；不要把项目配置写回分发套件
- 缺配置：每个技能按自己的最小输入契约继续；只询问会影响身份、权利、成本、外部行动或不可逆结果的缺项。可撤回的创意选择可采用明确标注的暂定方案

## 示例请求

最快开始只需说明 3–5 项：要完成什么、已有材料在哪里、面向谁/哪个平台、必须遵守的限制，以及交付到哪一步。没有特殊限制可直接说明；不必先填整份配置，也不必调用路由器才能使用单个技能。

- 独立策划：使用 `content-planning`，为一段产品使用演示设计观看理由、脚本与素材清单。先交方案，不生成
- 独立制作：使用 `content-production`，把我提供的素材剪成完整短片，声音和封面规格见我的项目配置
- 保留已有视频：使用 `publishing-delivery`，给这条已定稿视频补文案并整理文件夹；保留源视频字节。缺封面时先说明制作封面需要的输入
- 数据复盘：使用 `performance-analysis`，比较这些后台导出中发布后相同观察窗的内容，区分事实、解释和下一次测试
- 串联：使用 `social-media-router`，从当前简报推进到一条待发布内容；遇到缺失的付费/上传等授权停在对应动作前

## 可迁移的判断方法

研究证据先于热度结论；内容要有观看价值，运动和技术达标不等于有趣。先让画面里的行为、关系或形式成立，再写文案，不用抽象文案替随机动作补意义。身份与画风分开，完整成片与生成段分开，技术检测与实际视听检查分开，后台观察与因果证明分开。

历史作品可在方向选定后用于查重复、复盘或用户指定的延续创作，不强迫新创意从旧例开始。没有固定反转、镜头数、时长、分辨率、封面比例、声音政策、平台或工具。详见各技能按需引用的本地资料。

见 [配置说明](shared/config-guide.md)。所有项目取值留空；说明中的例子只是可选格式，不是默认品牌或默认偏好。运行环境和工具由执行者现场核实，凭据只引用外部安全运行时来源，不收集或随包保存秘密。请求方案不等于请求付费生成，生成不等于编辑或发布授权。以当前用户请求、实际权限及服务规则为准。
