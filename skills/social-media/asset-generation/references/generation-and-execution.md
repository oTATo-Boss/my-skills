# 提示词、提交与恢复

## 提示词保持可执行

格式服从用户和当前服务；没有指定时，可用“概述、参考、内容”三部分组织，不强制某个语言或模板。

- 概述：该段时长、画幅、场景与视觉语言、要发生的核心事件、在全片中的作用
- 参考：真实文件及职责；说明继承哪些身份/构图/状态，不继承哪些参考排版
- 内容：连续覆盖该生成段的时间、可见动作、变化、必要切点与声音；跨段约束紧凑清楚

全片时间与段内时间分开。时间区间不是镜头数量，模型也未必精确按秒表演；制作阶段按实际结果重新判断切点。不用密集动作和审美形容词替代可理解事件。

声音策略来自本项目：允许人声、需授权旁白、或无人物人声等都可以。没有选定声音策略时不替用户授权声音克隆；写进提示词不等于输出已遵守。

文件名与服务槽位一一核对。空参考明确为空；不用未存在的前段末帧，也不把提示词中的本地路径当成上传引用。交付成稿替换说明占位，离线模板保持明确“未提交”。

## 能力与成本预检

读取当前官方接口/模型文档或用户提供的有效接口契约，验证服务、输入类型、时长、分辨率、参考数量、异步状态、费用与取消条件。不要移植另一个服务的字段、应用 ID、回包结构或价格。工具、网络、凭据和支付能力都需现场核实。

提交前检查：

1. 当前用户请求确实覆盖这次实际生成及相应费用、服务和素材上传；配置中的拟定上限不能替代授权
2. 真实文件、许可/传输范围、完整提示词、输入类型、实际槽位和输出规格已核实
3. 单次与整批预算、币种/计费单位、任务数量和已有并发占用明确；不自动买余额、订阅或增加批次
4. 服务是否能硬性限制费用；客户端计时、取消请求或估算不等于服务端硬封顶。无法保证上限时说明风险并取得所需决定
5. 为每个逻辑任务准备唯一记录和恢复入口；多个依赖段按依赖关系执行，不强行并发

凭据只从当前环境支持且已授权的安全运行时读取，不写进代码、配置包、提示词、截图、请求日志或文件名。不绕过访问限制或安全警告。

## 有状态执行

推荐记录逻辑任务标识、非秘密输入摘要、状态、请求时间、服务任务 ID、官方状态和用量。最小状态区分准备、提交中、已接受、运行中、成功、失败、提交结果未知。

- 在提交前先保存“提交中”和关联信息；提交一次，收到任务 ID 立即保存
- 用已保存 ID 查询状态。短暂查询失败可重查，但恢复查询不应触发新提交
- 超时/断连且没有 ID：标记“提交结果未知”，从服务任务历史或官方恢复机制核对。不要把网络错误理解成服务没接单或没扣费
- 只有官方明确的幂等机制覆盖同一请求时才按其文档恢复；不能自己假设重发安全。仍无法确认就暂停重复提交，报告需要的核对或授权
- 进程重启读取原状态，不从头重跑。取消请求发出后核实服务端终态；本地等待超时不代表取消成功
- 成功后及时保存实际输出，验证文件有效；服务回包“成功”不能代替下载与媒体检查
- 达到请求终点或确认终态后停止相关监测，不自动追加任务

## 实际规格和费用

请求参数与真实输出分别记录；服务的清晰度标签不证明精确宽高。裁切、补帧、缩放或转码都另存衍生版本并披露，不能把低清放大称为原生高分辨率。

按每个真实任务的终态和用量求和；空值或暂未出账不是零，等待时长不等于计费时长，余额差可能含别的任务。输出签名地址可能带访问权限，避免写入通用交付、公开记录或技能。记录可追踪但不含秘密的服务 ID 与费用事实即可。
