# 项目配置说明

## 读取与优先级

1. 用户当前明确指令优先；配置提供本项目事实和约束。与真实平台限制冲突时指出冲突，不静默改规格
2. 优先读取用户明确提供的配置路径。只有明确知道其属于当前项目，才使用项目目录中已有的配置；不要搜索或套用其他账号、旧项目的私有配置
3. `project-config.template.yaml` 是空模板，不能被当作已经完成的配置。各技能没有依赖本文件才能理解的必填字段
4. 不要求用户填满整份模板。只读当前阶段需要的字段；输入也可以直接来自对话、素材清单或任务简报
5. `null`、空字符串和空列表在这份模板中都表示“尚未配置”，不是数值零、禁止或无限授权；项目若需要明确禁止，应填可读的具体限制

模板用于人工或模型理解，不承诺兼容某个执行程序的配置解析器。未来工具若读取它，应自行定义并验证类型，不把未经验证的字段拼接成命令。

## 字段解释与可选例子

- `project.goal / audience`：希望观众得到什么、面向谁。比如“让初次接触者看懂使用方式”；不要替用户编造商业目标
- `project.timezone`：明确时区名称或偏移；例如 `UTC`。整理时间与发布时间分开。未提供时可用标明的 UTC 临时整理，不能冒充用户当地时间
- `identity`：创作者表达身份、主体身份不变量、参考文件、可以变的风格与不能声称的内容。不是每个项目都有吉祥物、品牌或固定人设
- `platforms`：目标平台名称列表。要求不同才分平台版本；格式限制执行时再核实
- `video`：成片目标。帧宽高与比例应一致；精确时长需结合帧率及允许误差。生成片段时长放在 `generation`，不混成镜头长度
- `generation`：服务和官方文档由项目填写。并发数、费用、次数只是计划限制；必须核实当前能力和本次授权，不沿用旧批次许可
- `runtime_credential_reference`：指向执行环境支持的秘密管理器条目或安全运行时变量名，不填写密钥、令牌、认证头、签名下载地址或私人登录文件
- `audio.voice_policy`：例如“允许已获授权旁白”或“只允许器乐与环境/动作声”。不要默认所有项目都禁止人声；未确定时不替用户授权新的人声合成
- `cover`：独立于视频画幅。`3:4` 只是可能选项，不是本套件固定比例；还需适配实际封面裁切和安全区
- `tools`：可用工具的名称或环境内引用，空值时现场发现能力；不要因模板列了某类工具就声称有权限或已经使用
- `assets`：素材来源、许可、可上传范围及署名要求的索引；只提供当前任务需要的文件
- `delivery.folder_name_pattern`：可选示例 `YYYYMMDD_HHMM_内容名称`；时间依据、时区、文件名和额外字幕/署名文件均可配置。未指定时用清楚且不冲突的名称；默认不覆盖已有文件
- `analytics.account_reference`：项目内不含秘密的账号别名或已授权数据来源引用，不用于推断登录或账号控制权
- `analytics`：观察区间、时区、提取时刻、发布后窗口、主要指标和比较组。每个指标的含义、单位、累计/区间口径与分母在数据字典中记录

所有例子仅帮助填写；不构成新项目默认要求。不要把真实项目配置、账号身份、资产或历史授权复制回可分发技能。

## 阶段交接

可把下列内容放进项目自己的简报或清单，不要求采用固定文件名：

- 任务边界：用户要到哪个阶段、已明确批准什么、哪些动作仍缺授权
- 本次目标和已锁定规格；暂定项及其原因
- 策划：选定概念、观看理由、结构/分镜、素材需求、来源证据
- 素材：文件、职责、权利、实际规格、生成任务状态、验收与缺陷
- 制作：实际成片和封面路径、源文件对应、编辑范围、技术/视觉/声音各自检查结果
- 发布材料：定稿文案、文件夹清单、字节保留校验、用户可访问的交付位置
- 数据：来源、时间与指标口径、比较方法、观察结论和下一次测试

只交接下一阶段需要的信息。公开交付目录与含项目证据的工作目录分开；两者都不保存凭据。简明说明判断依据和取舍即可，不要求输出逐字思考过程。
