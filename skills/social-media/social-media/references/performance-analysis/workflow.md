# Performance Analysis

用实际后台证据回答明确问题，区分观察、可能解释和下一次测试。单条异常、低播放或审核标记不能证明创意因果或全账号受限。

## 阶段输入契约

需要分析目标、账号/平台范围、数据来源及观察时间范围。数据可来自已授权只读后台、导出或截图，不要求连接某个固定平台。缺后台访问时先分析用户提供的数据；缺时间/口径则整理可见事实并指出哪些比较暂不能成立。

项目配置可提供时区、区间、提取时间、发布后窗口、指标字典和分组方式。没有共享配置时本节与本地资料已足够。不得把配置账号别名当登录授权，也不为填表自动扩大数据访问。

## 工作方法

1. **先定义问题。** 是曝光、观看、留存、互动、关注、转化，还是执行质量？选择与目标对应的主指标，不因某列数字大就宣布成功
2. **采集并核对。** 保存来源、时间、单位、分母、累计/区间口径及必要标记，见 [数据契约](data-contract.md)。只收当前任务需要的信息
3. **建立可比组。** 对齐发布后年龄与观察窗，区分置顶、付费、审核状态及内容差异，见 [比较与测试](comparison-and-tests.md)
4. **给有边界的结论。** 把事实、解释、未知项和建议分开；小样本不声称统计证明，相关性不充当因果
5. **提出可检验改进。** 建议具体到可观察变更、目标指标、比较窗口及判定条件；用户只要求复盘时到报告为止，不自动发新内容或开启持续监测

## 输出

给出简短结论、来源/区间/时区、有效比较、重要限制和下一次实验。需要时附整理后的表格及指标字典，保持原始数据可追溯；缺值不填零，截图看不清不猜数。

不进入用户点赞、收藏的作品列表寻找灵感或复盘偏好。后台汇总的点赞数、收藏数可作为有明确口径的可选指标；这与浏览个人行为列表不同。分析不改变账号、帖子、权限或发布状态。
