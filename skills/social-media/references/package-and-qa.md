# 打包与质量检查

一篇内容对应一套能直接使用的素材；数量、格式和布局服从用户、项目及发布场景。视频、单图、多图都可交付，不强制每篇只有一个 MP4、一个 PNG和一份固定 TXT。多条任务逐篇交付，总合集可以附加，不能掩盖缺少某篇成果。

包装已有作品时保留原始输入字节，封面与文案另存；需要转码、剪辑、换声或重制时依据当前明确范围判断。内部凭据、任务回包、提示词、日志与中间文件不混入发布包；制作记录另存项目。

## 离线打包助手（可选）

`scripts/package_post.py` 使用 Python 标准库，接受一个或多个素材、可选独立封面及文案，按原扩展名和顺序打包，不依赖生成服务、剪辑软件或固定平台。标题显式传入，时间使用当前环境本地时区；可用 IANA 时区和时间戳参数覆盖，不硬编码地区。

```sh
python3 scripts/package_post.py --title '实际标题' --media /path/final.mp4 --cover /path/cover.jpg --copy /path/post.txt --out /path/delivery
python3 scripts/package_post.py --title '实际标题' --media /path/image-01.png --media /path/image-02.jpg --copy /path/post.md --out /path/delivery
```

示例路径需要替换。顺序按 `--media` 出现次序；封面已是首图时可不传 `--cover`。可用 `--timezone` 指定当前项目时区，`--timestamp YYYYMMDD_HHMM` 指定当地打包时间。文件系统不允许的标题字符仅在包名中清理，不改文案。已有目标不覆盖。

助手检查输入非空、ZIP完整性和打包字节与源文件一致性，原文案也不改写；在ZIP旁输出哈希与文件对应清单。它不解码媒体，不检查文案字段、平台规格、文字、画面或声音，不证明文件可播放和素材能发布。先做下面的实际验收，再按需求打包；已有适合的打包方法也可以使用。

## 发出前检查

- 内容与文案基于实际结果；视频运动可读，图文顺序清楚，表达按本篇目标完成。
- 有角色、品牌或产品约束时核对批准的识别特征和事实，不把参考里的默认画风当唯一风格。
- 声音按任务要求检查；没有播放或试听能力时列具体未验证项。
- 封面或首图符合当前比例、安全区与展示要求，逐字正确，缩略图重点清楚，与内容一致。
- 文案口吻与说话者正确，信息互补、事实准确，标签相关，不伪装验证了实时热度。
- 媒体真实格式、规格、解码与打开情况达到需求；打包已有素材时校验源文件哈希一致。
- 压缩包可解压，仅含所需交付文件，文件名、素材顺序和定稿对应；实际保存或上传成功后才称已交付。

缺能力时交付当前有效部分，具体说明尚缺什么；不交假媒体文件，不把本地保存说成远程上传，也不把素材准备说成已发布。达到本次完成条件即停止。
