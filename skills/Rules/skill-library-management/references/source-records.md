# 来源记录

每个独立 Skill 根目录保留一份 `SOURCE.md`，使整包移动、复制和导出后仍能追溯来源。嵌套子技能也有自己的记录，可引用父包证据；系统和插件技能由各自发行渠道维护，不写入其缓存目录。普通使用某个技能不要求补录全库。

## 字段

采用以下 Markdown 字段，便于人读与标准库审计；未知值写 `unknown` 并解释缺口，不留空。路径用相对路径优先；外部安装证据可用明确的本地路径或公共 URL，不能含凭据。

```markdown
# 来源记录

- skill: `example-skill`
- kind: `collected`
- status: `confirmed`
- source: https://github.com/owner/repository/tree/COMMIT/skills/example-skill
- version: 上游提交 COMMIT；未声明独立版本。
- author: unknown；未找到作者声明，仓库所有者不等于作者。
- license: unknown；当前证据未包含许可声明。
- collected_at: unknown；没有可靠安装日期。
- recorded_at: `2026-10-14`
- evidence: 安装清单 `../install-manifest.json` 的同名记录。

## 本地调整与边界

记录已知改编与原始包的差异；引用资源的许可沿用各自声明。
```

- `kind`：`collected`（外部收集）、`adapted`（二创／整合）、`local`（有证据的本地编写）、`unknown`（归属未确认）。
- `status`：表示当前 Skill 版本如何形成或接入的确认状态。`confirmed`（当前版本来源有直接证据，包括已确认的用户自研／二创）、`partial`（当前版本的来源链只能确认一部分或仅有待核实候选）、`unknown`（无可靠来源）。来源已确认不代表上游作者、许可、版本等字段也已确认。
- 本地原创或二创已经确认时，不因为缺少上游仓库、原作者、公开署名、版本或许可而把当前版本标为 `partial`／`unknown`。`author` 分清用户编写／整合部分与第三方原作者，缺口留在对应字段和说明中；汇总时把本地归属与上游资料缺口分开列出。
- `version` 区分技能版本、软件依赖版本、上游提交和资源快照；没有证据时写未知。文件夹哈希不是 Git 提交。
- `collected_at` 只使用安装记录或可靠导入记录，不以文件修改时间或本次补录日期代替。`recorded_at` 是本次建档／更新日期。

## 怎样核实和维护

1. 优先查看安装锁、包管理器 origin、Git 远程、导入清单和源码开发记录，再查看包内 README、元数据、许可证及下载归档。若有历史审计，保留其证据日期和限制；修改记录不能证明原创。
2. 原始来源与当前维护仓库分开说明。二创记录上游、改编范围和维护位置；用户提供的 ZIP 记录名称、已有哈希和导入日期。只有包来源可确定时，不推断其作者或上游。
3. 技能中引用的官方文档、工具仓库、Demo 或素材不自动成为技能的来源。缺少证据时记录候选与 `partial`／`unknown`；只在当前任务有必要时扩大检索，不为补字段运行安装、收费服务或全技能业务脚本。
4. 已有记录增量维护，不覆盖已确认信息。上游更新核对新提交、许可和本地改编；迁移更新有效的相对引用。原始许可证与版权文件保留，根级许可有继承依据时记录其位置和作用范围，不替第三方授权。
5. 自研／纳入开发仓库的技能先修改开发目录，再按项目规定同步独立安装副本；其他共享技能直接维护实体目录。来源文件不产生新的 Skill、索引拥有关系或安装副本，也不更改客户端链接。

完成后用 `audit_library.py --check-sources` 核对覆盖与记录结构，并报告仍未知的来源。记录存在、证据核实、源码安装一致和实际运行分别说明；仅补录资料不必运行各技能业务功能。

质量评分另存 [质量档案](quality-scoring.md)，引用此处的归属、上游路径和开发证据，不重复维护另一套来源真相。Star 的原始仓库与当前维护仓库分开，原创／深度二创贡献和使用记录各自举证；SOURCE.md 已确认不代表效果、依赖、Star 或调用频率已验证。
