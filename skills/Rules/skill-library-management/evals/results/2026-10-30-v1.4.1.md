# v1.4.1 新会话原生调用实测

日期：2026-10-30。最终批次使用本机 `codex-cli 0.163.0`，每例启动全新的 `codex exec --ephemeral`，未覆盖模型参数，沿用 CLI 默认模型及已有认证。原生发现临时项目 `.agents/skills` 中的 FERN 技能；除明确指定对照外，用户任务不点名 Skill。最终 **7／7 案例通过**，七个 thread ID 不同，详细命令、真实返回、线程及哈希见 [机器证据](2026-10-30-v1.4.1.json)。

结论：在这些受控 CLI 新会话中，项目规则能让 Agent 实际运行选择器，并按其返回执行业务 Skill；评分优先选型在此接入范围内生效。它仍不是宿主级数字优先级钩子，不意味着原生首个加载的正文一定是最高分，也不覆盖尚未接入规则的项目或桌面 UI。比较阶段可读取多个候选，业务执行与仅阅读资料分开计证据。

## 实测发现与修复

1. **旧接入允许只读档案后自行选择。** 初期六个探索会话虽然得到预期业务结果，日志却没有调用选择器。将正式接入模板及项目 AGENTS.md 改为：同类竞争且已有档案时，核实事实后运行 select，使用其结果；无档、待核验、明确指定和无关任务保留各自边界。最终四个竞争案例均补齐实际脚本路由证据。
2. **依赖相对路径基准易被混淆。** 初次阻塞案例检查了 Skill 内的 deps，而原要求是项目根；当时两处都不存在，所以只看最终选择不能发现错误。补充路径基准规则，并增加项目根依赖确实存在的反例。最终缺失／满足两例均核对项目根路径，选择及运行正确。
3. **只读会话不应被迫写候选文件。** select 支持 `--request -`，可从标准输入传入当前候选事实；专门的 CLI 回归验证了成功与非法 JSON 及输入档案不被改写。此次原生样本复用了已核实的请求文件，未把它冒称为原生标准输入分支测试。
4. **隔离启动及路径问题。** macOS 嵌套 Seatbelt 导致内部工具无法运行；关闭必需的 code-mode host 又使工具不可用。这些环境失败未计通过。最终只由外层系统沙箱保护真实目录，CLI 不重复施加内层沙箱，并关闭无关扩展、移除父 App 桥接字段。另发现 JSON ASCII 转义未正确屏蔽中文开发路径；改用 UTF-8 字面路径，逐一预检所有保护根及临时中文目录的读／写拒绝，并将探针 cwd 放在临时根。修复后重新创建项目并重跑全部七例；修复前批次不计作完整隔离证据。

## 隔离范围与可复核性

真实共享库、客户端 Skill 目录、全局指令及开发项目由外层策略拒绝读写；核心工具运行时为明确例外。真实目录只作访问拒绝验证，写入拒绝探针仅针对临时受控目录。未替换 HOME／CODEX_HOME，未复制凭据、改登录配置或整理真实库。原始日志中的全局 AGENTS 读取拒绝是隔离预期，不能与业务工具执行失败混为一谈。

最终原始日志位于系统临时目录 `native-skill-eval-28gdkckr`；它可能被系统清理。提交的机器记录只保留必要命令、输出、线程 ID、输入／原始轨迹及所测实现哈希，已替换用户目录路径，未复制原始 stderr、账号资料或运行缓存。按 [复现指南](../native-invocation.md) 可生成新目录重新采样；不覆盖旧样本。

正式生产逻辑 `quality_registry.py`、调用参考和 SKILL.md 的哈希与最终测试副本相同。离线与确定性回归合计 **59 项通过**：25 项结构检查、20 项评分／选型、14 项原生证据判据及真实系统隔离预检。原生证据反例覆盖仅自报、错误执行、未运行选择器、选择器返回与实际执行不一致、盲跑阻塞项、缺失进程／快照记录等情况。

项目文档、版本与来源记录同步到 v1.4.1；本次未提交、推送或同步本机安装副本。实际已安装 Skill 库的整理仍是后续独立任务。
