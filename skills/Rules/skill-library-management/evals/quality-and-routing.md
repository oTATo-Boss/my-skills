# 评分与调用验收

评分测试使用虚构仓库、来源和运行记录；网络部分单独实测当前仓库的公开元数据。不得把这些分数写入真实 Skill 档案。所有文件操作在临时目录中，脚本不发起 Skill 安装、全库整理或收费业务调用。

自动回归：`python3 -B scripts/test_quality_registry.py`。它验证算术及规则，不代替 Agent 的语义和质量判断。

| 场景 | 检查 |
|---|---|
| 六项权重与分数 | 权重和为 100；定性分数越界、布尔值、NaN／Infinity 失败；Star 和来源分由字段计算，不接受任意指定分。 |
| Star 真实含义 | 对数档与连续增长、合集折算；未知来源／归属不能计确定分；接口失败不变成 0，真实 0 保留；可选 gh 后备也必须返回有效成功数据。 |
| 证据 | 未验证／部分项不给确定总分，不归一化；效果／可靠性需实测；仅声明不等于来源已验证；未来证据、早于证据的评估日期、重复档案和重复运行 ID 拒绝。 |
| 当前性 | 指标到期或 assessed_version 变化使分数 stale；当前候选 revision 变化不复用原分；跨场景不混排。 |
| 用户指定 | 指定项优先于分数；旧分不否决当前条件已核实的明确指定；依赖阻塞时不暗中替代。 |
| 正常排序 | 高分不绕过任务匹配或运行条件；证据不足的竞争者可能影响结论时返回 needs_review；分差接近时依次比较原创／二创、当前版本同任务的真实成功记录及专业匹配。 |
| 只读 | CLI 校验／评分不写输入档案，错误数据非零退出；模板保持未验证状态，不能产生假赢家。 |

Agent 隔离回放：先按 [已有语义场景](semantic-audit.md) 生成七组实际文件，阅读真实流程、脚本和记录；运行 verify 后，以第 03 组的实际成功／失败输出为证据，在活动根外建立限定任务评分草稿和候选请求，再运行 score／select。评分要解释样本范围，不能把单次成功评为长期可靠；以当前依赖状态阻塞 alpha，保留并选择乙的 JSON 导出能力。具体评估与结果见 [v1.4.0 验收记录](results/2026-10-30-v1.4.md)。

调用接入分层验收：检查项目 AGENTS.md 与管理参考路径可达；对照官方文档和本机协议字段确认原生发现与调用边界；通过候选请求验证管理器排序。实际客户端新会话的自主隐式选型属于独立实验，未运行时明确标注，不能用单元测试替代。
