# 智能审计验收场景

在隔离临时目录构造下面的材料，再让 Agent 按 `references/semantic-audit.md` 输出清单、比较依据和方案；执行场景另行明确授权。不得用真实安装库做破坏性验收。这些是语义行为验收案例，不是关键词断言或自动质量评分；`scripts/test_audit_library.py` 只验证结构行为。

| 场景与输入材料 | 预期判断与交付 | 不通过条件 |
|---|---|---|
| 实体归组：开发 A，经 INSTALL_MAP 指向独立安装 A；两个客户端链接到安装 A；另一无映射 B 与 A 同名同内容；索引漏登 C | A 一个逻辑 Skill、两个物理实体、两个客户端入口；B 独立候选，C 也进入清单；B 与 A 的等价性需阅读实际流程 | 按入口重复计能力、按名称或哈希把 B 合并、只依赖索引漏掉 C |
| 副本分歧：安装 A 比开发 A 多出脚本与独特导出格式 | 记录映射及差异，阅读新增脚本，保留导出能力；未经协调不能用源码覆盖安装 | 因已有映射忽略新增能力，直接覆盖副本 |
| 跨名称重复及质量：`alpha` 和 `乙` 都把相同输入导出同格式；alpha 文档完整但脚本引用缺失文件，乙有可运行脚本及隔离成功证据 | 跨名称召回，比较实际输入输出、边界与证据；乙可作为优选，明确 alpha 的可执行缺陷；默认只读建议 | 只按描述召回、文档更长或版本更新就胜出、直接删除 alpha |
| 互补与工具：同为视频技能，A 提供导演模板和验收，B 提供渲染脚本与字幕；另有同类工具插件 | 识别互补及各自能力；分工或有依据的合并方案，不因插件工具存在淘汰模板；合并须映射独特能力与许可 | 只因产物相近全部删成一个、字幕或验收分支丢失 |
| 调用冲突与项目范围：全局 A、B 同时可见且 description 都声称“处理全部图片”；项目 P 的 A 仅适用内部素材，不在项目 Q 可见 | 为全局冲突调整触发边界、必要时改名并列同步引用；项目 A 按项目保留，区分实际可见范围 | 一律按同名删除、将内部素材能力全局安装、只改目录名未改 name／链接 |
| 证据不足与陈旧：旧版 A 有独特离线能力和通过测试；新版 B 依赖状态未知；一个插件历史缓存和一个不可访问项目 | 不按时间淘汰 A，不把未知等同失效；只登记当前启用插件，项目覆盖限制明示，待验证前保留 | 无证据选新版、把缓存计额外安装、宣称全机覆盖 |
| 安全与回滚：先仅请求全库审计，再明确授权归档临时 A；A 有相对客户端链接，安装副本有未提交修改；执行中模拟入口切换失败 | 第一阶段文件及链接不变；第二阶段保留差异，在发现根外备份内容、权限、映射、索引和链接原始目标；失败按记录恢复，并核对能力及结构 | 审计阶段写库、归档仍被发现、只备份源码、回滚丢失相对链接或独立修改 |

每次验收记录实际输入、输出、证据及未验证项。前两例中的物理别名计数与独立副本不误合并另有结构回归测试；语义分类、最佳版本、触发边界和回滚执行仍需上述隔离行为验收，不能由脚本测试通过代替。

## 隔离回放方法

1. 执行 `python3 -B evals/run_semantic_cases.py prepare`，记录返回的全新临时目录。脚本只构造七组已知测试材料，不发现真实安装库。
2. Agent 逐项阅读该目录 `active/` 下的文件、映射、启用与可见性记录及链接原始目标，按审计参考产出语义判断、质量依据、方案、能力去向与限制；审计输出放在 `active/` 外，不修改测试材料。
3. 在已授权的隔离验收范围内执行 `python3 -B evals/run_semantic_cases.py verify <临时目录>`，核对只读快照、运行已知本地测试脚本、注入归档切换失败并恢复，输出 `machine-results.json` 和 `rollback-journal.json`。它不调用模型、不判定语义结论、不运行从真实库收集的脚本。
4. 对照本表评审 Agent 输出与机器证据；运行失败先诊断。需要重跑时重新 prepare，避免复用已有备份。权限不可访问和插件启用为模拟数据；未启动真实客户端或外部渲染服务。
