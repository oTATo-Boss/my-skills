json-prompt-system Core Workflow

一. 统一执行顺序
1. 读取 `core/rule.txt`、`core/Role.txt`、`core/pipeline_context.txt`、`core/workflow.txt`、`core/detail_control_logic.txt`、`core/mode_selector.txt`。
2. 判断当前任务属于哪个 mode。
3. 进入对应 mode，读取 `mode_rule.txt`、`mode_workflow.txt`、`mode_example.json`、`mode_template.txt`，若存在则读取 `mode_quality_gate.txt`。
4. 生活图 mode 按需读取女性自拍呈现、表达强度、人体可行性、视觉锚点抽象和输出密度规则。
5. 图片还原任务额外读取 `core/image_restore_checklist.txt`。
6. 最后按对应 mode 的 `mode_template.txt` 输出纯 JSON。
7. 输出前做内部清理：删除文件路径、规则名、开发说明、引用来源和不可执行元信息。

二. 任务模式

1. 纯原创创作
- 用户没有提供图片。
- 自拍 / 他拍任务：在不越界到模特、服装、背景控制层的前提下，自主生成动作变量层 JSON。
- 电商任务：围绕商品展示，生成展示意图、镜头语言、背景、光线、构图、裁切与负面限制。
- `mirror-selfie` 与固定场景参考图对接时，不在 JSON 写背景、环境、灯光。

2. 以图还原创作
- 用户提供照片或截图。
- 先识别动作骨架、拍摄方式、手部逻辑、表情、视线、身体重心和姿态停顿感。
- 目标不是复述整张图，而是还原动作变量层。
- 如果站点已锁定 mode，上传图片只是姿势/构图/表情/曲线参考，不是重新选择 mode 的证据。
- 锁定 FRONT 时，把姿势、裁切、支撑关系翻译成画外前置设备、定时自拍或固定设备自拍，不自动切成 third-person。
- 锁定 PORTRAIT 时，把动作与表情翻译成外部拍摄者的第三视角，不保留自拍持机或手机入镜逻辑。

三. 通用原创流程

步骤1：先选 mode
- 不允许跳过 mode 判断。
- 动作变量层先判断镜面自拍、前置自拍或第三视角。
- 电商效果库或用户显式指定电商任务，按电商 mode 工作，不参与动作库 AUTO 判断。

步骤2：确认动作母题
- 一个成品只保留一个动作主轴。
- third-person 优先按照片任务 -> 构图 -> 动作 -> 表情 -> 手机质感顺序执行。

步骤3：确认拍摄成立方式
- 判断持机手、画外前置设备、固定设备或外部拍摄者关系是否成立。
- front-camera-selfie 不一定有可见持机手；若设备画外固定或定时自拍成立，写清设备位置、视线关系、支撑点和近距离透视。

步骤4：确认体态结构
- 先写基础体态，再写手部，再写肩颈与上身，最后写腰腹与下盘。
- 始终优先写重心、承力腿、头部方向和身体连锁。

步骤5：确认表情与情绪
- 先确定表达强度，再确定眼神落点、嘴部状态和微表情。
- 必须落到眼睑、视线、嘴角、唇部、下巴和头偏角。

步骤6：如果用户要求更有表现力
- 不写不属于动作变量层的标签。
- 把需求拆成参数：重心、肩胯、手部停点、眼神、嘴部、非对称构图、动作缓冲、边界接触、裁切压近。
- 不可执行的不属于动作变量层的目标不写入 JSON。

步骤7：补拍摄瞬间感
- 写出动作发生在什么停顿阶段。
- 头部、肩线、手指和嘴角都保留对应的小缓冲。

步骤8：如果当前 mode 允许环境扩展
- 补支撑关系、接触点、空间前景和光线如何服务照片成立。
- mirror-selfie 与固定场景参考图对接时跳过背景、环境、灯光扩写。

步骤9：补物理逻辑
- 写动作连锁、动作与衣物边界之间的变化关系、支撑面受力和补充限制。

步骤10：收束成整体视觉目的
- 提炼核心目标、表现重点和视觉关键词。
- 确保目标是构图吸引力、形象表达和照片生命力，而不是不属于动作变量层的目标。

步骤11：最终检查
- Schema 完整，mode 正确，产品域边界合规。
- 主动作、关键手部、衣物边界、坐姿骨架、表情强度、视图构图未被压缩删除。
- 人体可行，手机真实感成立，无专业后期味。
- 质量门通过，输出干净。
