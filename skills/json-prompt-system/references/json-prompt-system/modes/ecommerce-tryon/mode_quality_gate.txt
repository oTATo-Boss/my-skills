ecommerce-tryon Mode Quality Gate

硬性失败条件（任一命中即 FAIL）
- Schema 不符合当前 mode 模板，或混入其他 mode 的顶层结构。
- mode 判断错误：服装单品渲染、自拍动作或第三视角生活照被写成 ecommerce-tryon。
- 最终 JSON 输出污染：出现 `core/`、`mode_`、文件名、路径、规则名、README 或“参考某文件”等 agent 工作说明。
- 越权写入模特身份、人物外形、生活化自拍叙事、皮肤材质或与商品展示无关的情绪表演。
- 展示重点、镜头母版、裁切、手部交互和服装展示没有共同服务同一个商品卖点。
- 最终 JSON 复述具体服装款式、颜色、材质、图案、品牌、配饰名或商品名；只能写参考图锁定、结构边界、展示重点、镜头裁切和遮挡关系。
- 写入非商品展示内容，或把商品展示写成与商品无关的人物叙事。

一. 核心标准
- 最终结果必须像品牌电商镜头指令卡，而不是证件照 catalog 配置表。
- 必须让展示重点成为第一视觉。
- 必须让高级感落在镜头语言，而不是空泛形容词。

二. 结构检查
- 是否包含以下模块：
- 展示意图
- 背景控制
- 光线控制
- 构图控制
- 裁切控制
- 模特控制
- 服装展示
- 负面限制
- 若缺少 `展示意图`、`镜头母版` 或 `手部交互`，视为不合格。

三. 母版检查
- 是否明确选择了镜头母版。
- 镜头母版是否与展示重点一致。
- 如果展示重点是上方边界，却写成普通半身平均展示，视为不合格。
- 如果展示重点是参考表面关系，却仍让脸部成为主角，视为不合格。

四. 反证件照检查
- 是否出现正中对称站直。
- 是否出现标准平视证件照式半身图。
- 是否出现白底 + 直视镜头 + 双手无交互的默认安全方案。
- 是否把“商品清楚”误写成“人物呆板”。

五. 背景与光线检查
- 背景是否有品牌电商秩序感，而不是空白墙面逻辑。
- 光线是否有方向，而不是身份证式平均平铺。
- 光线是否明确服务上方边界、肩线、上身线条或参考表面关系等关键结构。
- 背景和光线是否都在衬托展示重点，而不是平均服务整个人。

六. 构图与裁切检查
- 视觉中心是否与展示重点一致。
- 景别、机位、主体位置是否真正服务展示重点。
- 裁切是否拉近了重点区域，而不是安全保守地把整个人平均装进画面。
- 是否明确禁止切坏关键结构。

七. 模特与手部检查
- 手部是否有明确态度：参与展示，或明确避让。
- 禁止手部完全失踪且没有镜头解释。
- 头颈、视线、表情是否增强品牌感，而不是回到直视镜头的 catalog pose。
- 模特是否在帮助衣服被看见，而不是单独表演人物情绪。

八. 服装展示检查
- 是否写清重点区域。
- 是否写清轮廓目标。
- 是否写清细节要求。
- 是否写清遮挡限制。
- 是否让人一眼知道“这张图重点要卖哪里”。

九. 负面限制检查
- 是否覆盖以下高风险项中的大部分：
- 证件照式构图
- 白底安全图
- 背景抢主体
- 光线吃细节
- 手部遮挡重点
- 展示重点与视觉中心不一致
- 参考外观漂移、结构错位、边界被切坏

十. 一句话标准
- 读完这张卡，模型应该知道如何把衣服拍成品牌电商图，而不是如何退回最安全的 catalog 照。
