ecommerce-clothing Mode Quality Gate

硬性失败条件（任一命中即 FAIL）
- Schema 不符合当前 mode 模板，或混入其他 mode 的顶层结构。
- mode 判断错误：真人上身、自拍或第三视角人物动作被写成 ecommerce-clothing。
- 最终 JSON 输出污染：出现 `core/`、`mode_`、文件名、路径、规则名、README 或“参考某文件”等 agent 工作说明。
- 越权写入模特身份、人物外形、生活化动作、情绪表演或与商品渲染无关的背景叙事。
- 展示目标没有围绕服装结构、边界、开口、厚度、受力、工艺关系或局部结构。
- 最终 JSON 复述具体商品款式、颜色、材质、图案、品牌、辅料名称或配饰名；电商外观只能写“参考图锁定/原样承担”与结构关系。
- 写入非商品展示内容。

一. 核心标准
- 最终结果必须像电商服装渲染协议。
- 必须高保真、强约束、可直接执行。
- 必须让服装结构和商品细节成为第一优先级。

二. 结构检查
- 是否严格保持五段式：
- 版本标记
- 任务定义
- 视觉提示
- 技术规格
- 负面限制
- 如果顶层结构漂移，视为不合格。

三. 任务定义检查
- 是否写清角色。
- 是否写清当前图像目标。
- 是否写清输入保真要求。
- 是否明确强调外观由参考图锁定，并保留结构、边界、受力和工艺逻辑。

四. 视觉提示检查
- 主体结构是否写清当前任务的视角或局部部位。
- 是否写清立体成立逻辑。
- 是否写清开口、厚度、边缘、层次或受力关系。
- 细节保留是否列出必须保住的关键信息。
- 环境是否保持低干扰商品图逻辑。

五. 任务类型检查
- 如果是主视角：
- 是否能看出正面、反面、侧面或 45 度中的哪一种。
- 是否强调 Ghost Mannequin 成立。
- 如果是局部特写：
- 是否能看出当前是哪个工艺部位。
- 是否强调工艺关系而不是简单裁切。
- 如果是功能展示：
- 是否能看出厚薄、内里或口袋开合的结构逻辑。

六. 环境与技术检查
- 是否默认白底或低干扰商业背景。
- 是否使用商业棚拍柔光或软定向光。
- 是否只允许帮助结构成立的内部阴影。
- 技术规格是否保持高分辨率、高锐度、写实商品渲染，且不命名具体颜色/材质/图案。

七. 负面限制检查
- 是否至少覆盖以下大类风险中的大部分：
- 真人写入
- 假模特感
- 塑料感
- 贴图感
- 错误工艺
- 错误透视
- 脏背景或错误阴影
- 模糊噪点

八. 单值检查
- 是否出现“或 / 可 / 可选 / A/B / 根据情况”。
- 若出现多选表达，视为不合格。

九. 一句话标准
- 读完这份 JSON，模型应该清楚知道“怎么把这件衣服渲染成可卖的商品图”，而不是“怎么写一段时尚描述”。
