# 网页视觉方向

## 使用边界

用户要求和项目已有设计系统优先。沿用现有组件、样式和依赖；修改限定在本次目标内。下方参考文件是按需使用的配方，其固定数值、字体、色彩、版式和输出格式均可依项目调整。
只读取当前任务需要的参考；不默认加载整个库或全部总技能。额外工具、素材生成和新依赖由实际需要决定。
库中的版本、外部链接和代码片段来自旧合集；涉及实际安装或 API 时，先核对项目现有版本和对应官方资料。静态设计或素材示例不代表已实现的数据、交互或持久化。
已有专用技能、工具或组件能完成目标时复用它们，避免重复启动另一套流程。

## 执行方法

从页面目的、受众、品牌或参考、真实内容和设备约束推导视觉方向。已有产品的小修改保持原方向。

1. 选择一个主方向，明确布局、字体角色、颜色语义、材质、媒体处理和动效强度。可以吸收一个辅助细节，不叠加多个完整风格系统。
2. 内容优先：产品工作区重操作清晰度与可扫描性；官网与作品集可强化叙事、图片和表达。区别展示界面与可操作的产品界面。
3. 只在关键方向确有分歧时做少量差异明确的方案；已有参考足够时直接实现。不默认十方案、子代理、盲评或新增分支。
4. 把选定方向映射到现有 token、组件和响应式规则。主题、侧栏、字体或布局形态由目标决定，不以某种审美偏好为普遍禁令。
5. 用真实文案、图片和数据长度检查首屏与后续节奏。生成图片只在需要视觉探索或缺少素材时使用。

## 按需参考

- 选择整页风格时先看 [styles.md](references/styles.md)，然后只读选定风格。
- 官网结构或转化文案：`landing-page`；套餐与定价信息：`pricing-page`。不编造客户、收益、评价或指标。
- 设计方向推导：`design-taste-frontend`；生成 DESIGN.md：`stitch-design-taste`，无需特定外部应用。
- 仅在用户明确要 GTE 品牌时使用 `gte-design` 的 token、字体和组件；`loop-tracker-design` 是可选仪表盘风格，不能自动覆盖其它项目。
