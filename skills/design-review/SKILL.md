# 设计检查与优化

## 使用边界

用户要求和项目已有设计系统优先。沿用现有组件、样式和依赖；修改限定在本次目标内。下方参考文件是按需使用的配方，其固定数值、字体、色彩、版式和输出格式均可依项目调整。
只读取当前任务需要的参考；不默认加载整个库或全部总技能。额外工具、素材生成和新依赖由实际需要决定。
库中的版本、外部链接和代码片段来自旧合集；涉及实际安装或 API 时，先核对项目现有版本和对应官方资料。静态设计或素材示例不代表已实现的数据、交互或持久化。
已有专用技能、工具或组件能完成目标时复用它们，避免重复启动另一套流程。

## 执行方法

从用户指定的页面、路径或问题开始，先检查真实页面与相关代码。评价以用户目标和项目已有设计系统为准。

1. 优先检查影响任务完成的问题：信息层级、主要操作、阅读、键盘与焦点、空/加载/错误状态、移动布局。再检查对齐、颜色与材质一致性。
2. 动效问题检查实际播放与中断；性能问题先测具体路线或交互，区分首屏、长会话、滚动和路由切换，不能从样式复杂程度直接断言卡顿。
3. 每条发现给出实际位置、现象和影响。区分可观察缺陷、对目标的偏离和可选审美建议，不要求统一用表格或固定打分。
4. 仅审查的任务交付发现；授权修复时优先范围内根因，保持布局、文案、品牌和数据契约，避免顺手整页重做。
5. 用对应页面和交互复查已修复问题。静态检查、构建通过和真实界面验证分别报告；明确未验证的路线或设备。
