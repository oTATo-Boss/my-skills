# Video Production

把当前创意与实际素材推进为可制作、可追溯、可恢复的成果。沿用调用项目的目录、任务系统、角色、编号和验收规则。四个模块共享批准的剧本、资产、制作状态与版本；模块是本包方法文档，无需安装或发现旧四个 Skill。

## 选择最短执行路径

先读取当前请求、相关简报、已批准成果和最近检查点，确定交付终点与可修改范围。复用已知事实，日常制作选择自主判断；影响关键成果而无法可靠判断的缺项才询问。用户要求先分析、只出方案或先确认时停在对应边界。

| 当前任务 | 按需加载模块 | 停止条件 |
|---|---|---|
| 梗概、大纲、分场、剧本或对白修改 | [编剧](modules/screenwriting/guide.md) | 交付请求的写作阶段；涉及已有设定变动时补连续性影响说明 |
| 拆任务、安排依赖、多角色交接、项目恢复 | [统筹](modules/orchestration/guide.md) | 可执行工作包／检查点；按用户目标决定是否继续制作 |
| 镜头穿帮、跨集状态、设定改动影响 | [连续性](modules/continuity/guide.md) | 有依据的状态增量、问题和受影响单元；不擅自改剧情或重生素材 |
| 镜头生产、剪辑声音字幕、导出与验收 | [制作交付](modules/pipeline/guide.md) | 用户要求的真实产物及检查证据，或具体阻塞 |
| 完整新片／系列 | 统筹 → 编剧 → 连续性 → 制作交付，按阶段读取 | 请求的交付版本完成并通过所需检查 |

一次只读取当前阶段的方法与其需要的参考资料。完整任务中统筹持续维护依赖；连续性在剧本、镜头衔接、设定修改和组接时按需复核，不固定只执行一次。单个阶段不要求加载全包或重建团队。

## 共享状态与交接

所有模块复用同一份项目状态，避免另立冲突的台账。小任务只写必要增量，大项目按集／场／镜头拆分。

- 目标：请求范围、内容类型、单片／系列形态、制作路线及交付规格。
- 批准依据：剧本、设定、角色和资产的实际版本；提案与批准结论分别标注。
- 制作单元：稳定编号、负责人、输入版本、依赖、允许写入位置和完成条件。
- 连续性：单元进入／退出状态，以及已确认的变动生效范围。
- 产物证据：真实文件、输出版本或哈希、检查方式、结果及未验证项。
- 恢复信息：外部任务 ID、真实状态、阻塞和下一项有边界的行动。

结构示例见 [工作包与检查点](modules/orchestration/references/handoffs.md)、[连续性台账](modules/continuity/references/ledger.md) 和 [制作清单](modules/pipeline/references/manifest.md)。采用项目已有字段和文件即可，不强制新建数据库或目录。

## 修改与恢复闭环

1. 编剧或设计变更先记录新版本，并保留原批准版本和稳定单元编号。
2. 连续性模块比较新旧事实，识别受影响的状态、镜头和集数；没有依赖变化的成果继续复用。
3. 统筹模块更新必要依赖与返工工作包，明确负责人及输入版本。
4. 制作模块只重做获授权的部分，核对新输出和相邻组接，再更新对应交付版本。
5. 中断后核对已完成文件、输入版本和外部任务状态，从最近可靠检查点继续；不凭旧聊天推断已完成。

外部生成提交前保存请求意图，提交后保存任务 ID。超时或响应丢失时先查询恢复，未知状态不等于失败，不盲目重复付费请求。

## 协作与工具边界

- direct-video 按需提供导演判断与视听方向；本 Skill 负责将批准方向落实为脚本、工作、连续性与交付。
- 人物资产按需使用 character-design；单镜头／多镜头生成提示词按需使用 single-shot-prompt／multi-shot-prompt；参考方式按需使用 r2v。检查真实入口和工具能力，缺少可选技能时说明限制，不声称已调用。
- social-media 负责社交场景的内容包装和后台分析；本包不因完成成片而自动开始发布或运营。
- 调用项目或用户明确授权并行时，可按稳定输入与互不覆盖的产物使用现有子 Agent；否则顺序执行同一套工作包。共享状态保持单一写入负责人，自检如实标注 self。
- 本包不安装工具或绑定特定渲染器；外部上传、付费、发布等按当前授权执行。

## 完成与交付

按请求交付脚本、状态增量、工作包或真实媒体文件；过程草稿和原片不能替代用户要求的成片。说明实际版本、完成检查、重要缺陷和下一步依赖。技术检测、实际看画面、连续播放和实际试听分别记录，未执行不写通过。旧审核只适用于对应产物版本，新输出重新核验。达到用户目标后停止。
