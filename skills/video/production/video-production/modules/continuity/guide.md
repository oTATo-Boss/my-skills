# Production continuity

Keep story state and produced evidence traceable. Use the project's existing scene IDs, version records and ledger; do not create a separate story authority. The script or designated creative owner decides canon. A generated frame is an observation, not an automatic change to canon.

## Build only the ledger this task needs

Read the approved script/treatment, asset references and relevant preceding/following units. Identify story order separately from shooting/render order. For non-linear stories track both story time and audience presentation order. For series also track the knowledge each character and the audience have acquired.

Record:

- Character identity, distinguishing features, wardrobe, injuries, emotion only where it affects the next action, and knowledge.
- Props: holder, location, quantity, orientation, open/closed/broken state and transfers.
- Location: entrances, spatial axes, light/time/weather and persistent set changes.
- Shot handoff: pose, movement direction, eyeline, hand used, object state, sound and visible background relationships.
- Source asset and version behind each approved appearance; distinguish design references from final rendered evidence.

Small edits need a short delta, not an exhaustive fictional biography. For an explainer or product film, track labels, units, model assumptions, product configuration and diagram conventions instead of inventing character records.

Read [ledger.md](references/ledger.md) when creating or auditing a ledger; it provides story-state and evidence examples.

## Compare intent with evidence

1. State the expected entry and exit state from approved sources.
2. Inspect the relevant actual frames, action interval, dialogue and audio when those modalities are available. A still image cannot verify the full handoff action or sound.
3. Compare adjacent cuts and later dependent scenes. Distinguish intentional discontinuity, ordinary coverage differences, a material contradiction and unavailable evidence.
4. Report a defect with unit/timecode, expected state, observed state, source version and impact. Do not mark `passed` when only a script was checked but produced footage is requested.
5. Return a targeted repair to the owner: regenerate/replace a shot, change the edit boundary, adjust a prop/color/label, or seek a story decision. Do not silently rewrite the plot to explain a production mistake.

## Apply a canonical revision

When the authorized story or design owner changes a fact, preserve the old version, write the new fact and its effective story interval, then find dependents. Mark those units for recheck with the specific reason. Do not blindly invalidate every shot in the project or treat all later scenes as dependent when their inputs are unchanged.

Example: moving a key transfer from S03 to S05 affects S03 coverage, S04 ownership references and S05 staging. It does not necessarily invalidate S02 or an unrelated exterior shot. If a background asset version changes, identify every shot using that version even when its scene occurs earlier.

Deliver the updated ledger/delta, mismatch list and affected-unit set. Label observations, proposed repairs and approved canonical changes separately, including who made the decision and its source artifact.
