# 生成方式、时序、质量与失败修订

## 索引
能力条件 → 生成方式 → 生成单元 → 时间落实 → 源质量 → 失败诊断 → 经验使用。

## 1. 只核对会改变当前方案的能力
沿用当前项目和执行工具提供的有效信息；影响任务的缺项才补查。能力变化后复核相关判断。

| 需要的控制 | 核对什么 | 对参考方案的影响 |
|---|---|---|
| 角色/服装/场景/风格参考 | 图片作为普通参考、主体参考还是端点帧；能否分别绑定用途 | 决定拆开提供、整理参考板，或先准备可理解的组合状态 |
| 动作、效果与运镜 | 是否接受视频；参考、编辑和运动控制的实际含义 | 决定原片直接输入还是只用于分析，是否需要预处理 |
| 空间和连续路径 | 是否理解俯视、深度、姿态、白模等表示 | 决定采用何种表达，或把其效果列为针对性验证项 |
| 音色、台词与声音 | 音频用途、长度、说话人绑定、声音和画面的组合限制 | 决定声音输入与角色对应，以及需要交接的声音缺口 |
| 时长、画幅、输入规模 | 当前模式下的限制和组合条件 | 决定有效片段长度、本次素材子集与构图准备 |
| 预览到正式质量 | 可用档位、关联任务方式、种子与参数复现条件 | 决定直接正式生成还是先试验；记录需复核的变化 |
| 局部修订与延续 | 支持的对象/时段范围、上下文条件、原内容保留程度 | 决定能否保留可用部分及需要哪些连接状态 |

区分“当前入口已声明”“相近条件有实测”“未支持”“待核验”。模型宣传说明某能力存在，不自动证明正在使用的应用已开放；相同功能名称也不代表相同控制精度。已有相近实测优先作为效果判断依据。

## 2. 按目标选择参考使用方式
| 目标/现状 | 优先评估的方式 | 必要输入判断 | 需要验证的边界 |
|---|---|---|---|
| 已有明确主体，简单动作与机位 | 直接图像参考生成 | 身份/外观及可见状态是否足够 | 身份与运动是否同时稳定 |
| 已有完整目标静帧，强调开场一致 | 首帧引导 | 静帧是否适合动作起点，画面外空间是否充分 | 后续状态能否从首帧合理发展 |
| 必须到达具体结束状态 | 支持的首尾帧或关键状态引导 | 起点/终点一致性及过程要求 | 中间过程和动作机制仍需检查 |
| 多角色、服装、场景等分开定义 | 支持的多参考生成 | 属性分工、冲突与本次输入规模 | 多份输入的属性是否被正确使用 |
| 在既有视频上换人/换物/改状态 | 当前入口支持的参考或编辑方式 | 被替换范围、保留范围和目标外观 | 原身份残留、背景/动作意外改变 |
| 仅复用参考视频的动作/运镜/效果 | 选择性参考；必要时提取控制信息 | 运动资料是否保留必要机位与空间关系 | 去外观处理是否损伤动作或仍带入旧外观 |
| 复杂连续走位和机位 | 场景布局/路线、视频预演或白模参考 | 路径、遮挡、地标与目标外观的对应 | 当前入口的空间/运动跟随程度 |
| 延续已通过片段 | 支持的延续方式 | 末端的姿态、运动方向、空间、光线与声音状态 | 连接处连续性与后续漂移 |
| 只有局部不合格 | 支持的局部编辑或补充生成 | 修改范围及两侧连接状态 | 改动是否越界，未改部分是否仍稳定 |

上述是方法选择，不指定模型、服务或插件。执行方负责编码实际参数。纯文字已能充分定义开放式简单目标时，可得出“无需新增参考”的结论；指定身份/产品或精确空间则需要相应依据。

## 3. 生成单元：先保留作品要求，再控制耦合
先识别哪些变化必须连续发生，哪些本来就有镜头边界。根据具体入口的表现，判断同一单元的控制是否仍可理解和修订。

一个短而简单的动作可整段生成；多个造型若有明确切点且精度要求高，可向导演提出按造型或事件边界组织素材的建议。连续转身本身是转场、或用户要求真实一镜到底时，优先保留连续动作与空间，通过明确状态、路线或预演补强。

每个需要独立生成的单元要有：共同身份/风格依据、入口状态、事件结果、出口状态和衔接要求。参考资产按对应单元选择；镜头拆分与全片结构由导演确定。

当完整一镜到底要求超出当前入口可用时长，明确“要求与能力不匹配”。可评估支持的延续或其他符合要求的入口，给出连续性风险；采用剪切会改变原要求，交导演裁决。

精确文字、版面或独立运动若无法可靠生成，写明需要的独立素材、遮挡、相机或后期控制条件；具体如何结合代码、合成与生成由导演和后期方法负责。

## 4. 将已有时间轴落实为可用素材
### 三种精度
- **事件先后**：A 完成后发生 B，例如关门恢复外观后再驶离。
- **相对节奏**：A 是快速过渡，B 是主要展示；给可观察的节奏目的。
- **精确节点**：明确秒数或帧数及允许偏差，例如音乐切点、短回闪、指定停顿；使用项目已有精度要求。

每个重要事件写：目标时段/顺序、主体进入状态、实际动作、动作完成状态、相机动作与停点。需要剪辑时，再写素材应提供的可用区间和合理前后余量。让生成素材具有调整空间，不等于增加空等或拉长整段。

复刻已有镜头表时，复核目标时间到素材状态的对应，不重新制造一套不同时间轴。需要精确节奏时，由执行方提交实际事件位置与可用区间，后期据此落实。

### 时序偏差的判断
| 实际偏差 | 优先判断 |
|---|---|
| 动作完整但发生时间偏移 | 是否有足够可用区间通过剪辑对齐；检查动作起止和相邻连接 |
| 同一动作持续过长 | 压缩后表演/物理运动是否仍自然；必要时补合适速度的动作 |
| 关键展示过短但有完整姿态 | 判断延长是否改变人物、布料和镜头运动观感，或需要更多真实动作内容 |
| 关键动作/造型根本没出现 | 这是内容缺失，需要补生成或局部编辑，而非仅调整时间 |
| 事件先后错误 | 修正状态依赖或控制参考，检查是否能局部修订 |
| 一镜到底中的路径/停点错误 | 核对主体路线、机位路线与时间锚点，按必要程度补强预演 |

帧率适配、插帧和速度变化是后期处理条件，不等同于新增表演。由实际动态检查判断自然度；原始素材和处理结果分开检查。

## 5. 选择源质量与试验方式
先定义成片中必须可辨的细节、目标观看尺寸、裁切/重构图幅度和材质风格，再选实际入口能提供的源质量。清晰度要求是可见结果，分辨率只是其中一个条件。

### 直接生成
现有经验稳定、单次成本合理，或低清不能验证主要风险时，直接采用合适档位。720P 可用于满足实际需求的任务；需要更高源细节时使用对应可用质量。输出为 1080×1920 不自动要求每个任务都采用同一生成档位，也不等于源素材已具有相应细节。

### 低清验证后正式生成
只有试验能降低当前不确定性且值得其成本时使用。480P 等低档可以验证布局、事件或动作方向；脸部、织物或细小产品标记应在正式质量验证。

记录实际复用条件：
- 支持关联预览任务：按入口公开语义沿用输入与任务关系，正式结果仍复查重点属性。
- 只有种子可固定：保留输入和已定参数，跨分辨率/时长/模型版本变化后的输出视为待复核版本。
- 没有可靠关联机制：先判断低清结果是否有足够迁移价值；不值得时直接使用正式质量。

输入参考、提示词、模型/工作流版本、种子及关键参数需要由执行方保留，以便解释试验结果；R2V 只明确需要哪些可比较证据。

### 四种质量信息分别表达
| 信息 | 记录内容 |
|---|---|
| 生成源 | 实际尺寸、帧率、源文件及当前生成档位 |
| 清晰度处理 | 无处理、普通缩放、超分或重新生成等实际方式 |
| 输出规格 | 最终画幅、尺寸、帧率和用途 |
| 感知质量 | 目标播放大小及必要细节处的身份、皮肤、织物、边缘和动态纹理 |

标称高分辨率与“锐利”不能单独证明自然细节。参数步数、量化、加速与画质的关系以当前方法的对照证据判断。

## 6. 失败诊断：用证据缩小原因
| 观察现象 | 优先检查的证据 | 可以提出的最小修订 |
|---|---|---|
| 人脸不对或继承原模特 | 身份图可读性、图间一致性、原视频用途、实际上传映射 | 修正身份依据/绑定或调整冲突参考；保留有效动作依据 |
| 穿错衣、背面变化、材质跑偏 | 该造型与可见方向的资料、穿法、风格和实体对应 | 补缺失状态，或在资料已齐时测试参考组合/执行方式 |
| 数量与布局错误 | 参考是否清楚表达独立对象、层次和位置；实际输出时间点 | 补清楚布局或关键状态；入口仍不可靠则明确控制限制 |
| 空间/方向错误 | 各视角是否同一空间，坐标/屏幕方向、路线与机位是否冲突 | 修正冲突视图或明确路径，必要时补运动/空间预演 |
| 动作、效果或切换先后错误 | 原时间轴、状态依赖、实际事件位置 | 补明确前提与完成状态，评估已有素材调整或局部补内容 |
| 油腻、塑料感、假高清 | 目标风格、参考原图、原始输出、后期输出的同一区域 | 先区分输入/生成/后期阶段，再选择有辨识价值的对照变量 |
| 音色/台词对应错误 | 说话角色、干净样本、时段与实际绑定 | 修正映射或样本，重查声音与可见说话者的一致性 |

缺陷记录只写观察范围内的事实。实际素材不可用时给出候选原因和验证需求，保留不确定性。

对照试验保持可保持的条件一致，只改变能区分原因的关键因素；不可避免改变多项时记录混杂因素。结果要同时看画质、身份/动作稳定、耗时与成本。重复试验是否值得，由当前不确定性和项目约束决定。

## 7. 使用已有经验
从项目已有经验记录中找条件相符的案例：目标、参考形式、关键控制属性、入口能力与结果。稳定复用的是“在什么条件下采用什么方法”，不是某次参数或素材组合本身。

归档最小内容：观察问题、输入条件、改变项、实际结果、适用范围。没有实际结果的方法保留为候选；单次成功记录为案例；经过重复检验再提高复用优先级。维护与检索由使用者现有记忆机制完成。
