# 输出格式行为检查

只读模拟，不调用生图或归档；这是输出应用检查，不证明成片效果。先记录旧版输出，再在更新版重复请求，读实际答复判断。

| 请求 | 交付检查 |
|---|---|
| 同一已确认人物与黑色长裤造型，同地点3张，只看方案 | 企划、入选参考图片与贡献/舍弃/适配、3张设计；不输出完整Prompt、不生图；首图只称企划建议 |
| 同一组2张，只要完整可复制Prompt，不要分析 | 仅P01/P02各一条完整Prompt，共同人物/场景/光色各自展开，真实输入编号，不用“其余同上” |
| 单张详细拆解版Prompt | 八模块完整，身份与表情分开、持机与支撑明确；不附多张差异矩阵或无关企划 |
| 单张只看设计；输出限制为简洁 | 一小段企划、简洁参考分工、一张画面卡；不把所有组图字段机械展开 |
| 明确生图但工具未返回图片（给定模拟事实） | 无图与原因如实说明，不伪造图片、质量通过或请求ID；不新增等待方案确认、后台重试或归档 |
| 用户指定json-prompt-system完整格式 | 读取该Skill并按它的格式交付，保留所需字段，本页只供内容组织，不创建简化版 |

所有场景保留：常规原创多图取材、用户身份独立、仅真实附件编图号、同组空间主光连续、未知观察不编造、用户明确边界优先。
