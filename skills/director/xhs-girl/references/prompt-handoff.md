# 从摄影决定到可执行提示词

xhs-girl 决定照片怎样好看，JSON prompt 把这套决定组织成最终输入，生成工具执行当前分辨率、画幅和真实参考上传。每层都使用本次摄影设计。

## 标准交接

1. 根据[摄影卡](../templates/shot-card.md)完成 `摄影设计` JSON。复制[完整例子](../examples/README.md)修改，不混入旧动作卡的“生活直出成像约束”。
2. 联用 `json-prompt-system` 时读取其 `references/photography/README.md`，使用新摄影入口。拍摄关系仍选 third-person、front-camera-selfie、mirror-selfie 或 ecommerce-editorial，`--photography` 指明本次使用完整摄影设计。用户只要 JSON 时加 `--json-only`。
3. 实际人物档案按需传入。先阅读其身份和造型条款，当前创作若与旧档案的衣服/成像默认冲突，将本次明确选择写进参考分工与人物字段。档案只含身份时原样传入即可。
4. 每张真实上传图在 `参考分工` 里按顺序写 `图号`、`负责`、`保留`、`调整`。整张摄影参考可负责光线、裁切和透视；人物参考负责身份。文字中没有上传的图只写成构思来源。
5. 查看最终拼装正文，核对它是否保持两三项成功条件；实际调用只提交这一份正文。

从 JSON prompt Skill 根运行的例子：

```bash
python3 scripts/compose.py third-person --photography --resolution 1K \
  --ratio 3:4 < /absolute/path/record-store.json
```

没有安装 JSON Skill 时，直接保留摄影卡的完整结构与可见描述，按身份与参考分工拼成正文。用户要自然语言时可转换成紧凑段落，保留相机、边界、人物、空间、光色、质感与优先条件。涉及实际工具参数时使用该工具支持的参数。

## 提示顺序与复杂度

正文先交代画幅和分辨率、参考分工，再写摄影设计。相机位置、裁切、人物关系和光线优先，材质与细小配饰随后。较弱生图模型首轮抓住两三项核心条件，其他细节保持支持作用。同一个身体部位只写一个相互兼容的位置。

旧 JSON 模式仍可供原有调用使用，默认包含生活直出偏好。xhs-girl V2 的完整摄影设计走新入口，避免上层选了强俯拍、静态摆姿、柔化或夜街直闪，下层又无条件插入平视低机位、动态抓拍、极轻处理等另一套决定。把主动摆拍的日常照片切到时尚大片模式也不能自动解决摄影关系。

## 提交前的语义核对

| 同时出现的描述 | 本次需作出的决定 |
|---|---|
| 高位俯拍、平视为主 | 按本次摄影卡的实际位置保留一套 |
| 大面积暗部、均匀自动提亮 | 明确哪些脸部亮、哪些地方可以暗 |
| 皮肤柔和、不磨皮 | 以本张选定的成像处理为准 |
| 近距广角、远处长焦压缩 | 选择符合本次透视的一组位置与范围 |
| 看镜头、刚好扫向别处 | 把视线落实到最终一瞬的落点 |
| 身份参考的旧衣、当前新造型 | 分别声明保留身份与调整造型 |
| 用户1K、正文原生4K | 正文和工具参数一致，文件尺寸最后核实 |

脚本能检查必填、字段类型、图号顺序和拍摄关系，语义审核需要读最终正文。任何脚本通过均不证明实际画面已经实现这些关系。
