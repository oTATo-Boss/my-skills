# 从摄影决定到可执行提示词

xhs-girl 决定照片怎样好看，JSON prompt 把这套决定组织成最终输入，生成工具执行当前分辨率、画幅和真实参考上传。每层都使用本次摄影设计。

## 当前交接（2026-11-14 回退后）

`json-prompt-system` 已按用户要求回退至 v3.1.0，不再提供显式摄影入口。`--photography`、`--resolution` 与 `references/photography/README.md` 已撤回；本包的 `摄影设计` 卡不能直接传入该 Skill 的拼装脚本。

1. 根据[摄影卡](../templates/shot-card.md)完成本张设计，[完整例子](../examples/README.md)保留为设计参考。
2. 需要交付本包摄影方案时，直接将摄影卡组织成正文；用户只要 JSON 时交付原卡。不要再调用已撤回的摄影参数。
3. 每张真实上传图在 `参考分工` 中按顺序写图号、职责、保留和调整。读取实际人物档案，协调身份、服装与成像要求后，再核对最终正文。
4. 用户明确需要 json-prompt-system v3.1.0 输出时，按该 Skill 原有模式重新生成匹配的动作卡，再使用其正常拼装命令。四套固定正文及原有规则照常生效；不得把摄影卡直接当成旧动作卡，或宣称旧模式能够无损承接所有摄影选择。
5. 工具执行当前画幅、分辨率及真实参考上传，最终核实文件；提示词中的规格不能代替工具设置。

## 提示顺序与复杂度

正文先交代画幅和分辨率、参考分工，再写摄影设计。相机位置、裁切、人物关系和光线优先，材质与细小配饰随后。较弱生图模型首轮抓住两三项核心条件，其他细节保持支持作用。同一个身体部位只写一个相互兼容的位置。

json-prompt-system v3.1.0 的生活照模式包含固定成像偏好。若本张摄影设计与这些偏好冲突，交付本包独立摄影正文，不混拼两套要求；只有按原模式工作的任务才走旧动作卡。主动摆拍的日常照片也不能仅为避开限制而自动切到时尚大片模式。

## 提交前的语义核对

| 同时出现的描述 | 本次需作出的决定 |
|---|---|
| 高位俯拍、平视为主 | 按本次摄影卡的实际位置保留一套 |
| 大面积暗部、均匀自动提亮 | 明确哪些脸部亮、哪些地方可以暗 |
| 皮肤柔和、不磨皮 | 以本张选定的成像处理为准 |
| 近距广角、远处长焦压缩 | 选择符合本次透视的一组位置与范围 |
| 看镜头、刚好扫向别处 | 把视线落实到最终一瞬的落点 |
| 身份参考的旧衣、当前新造型 | 分别声明保留身份与调整造型 |
| 用户1K、正文原生4K | 正文和工具参数一致，文件尺寸最后核实 |

脚本能检查必填、字段类型、图号顺序和拍摄关系，语义审核需要读最终正文。任何脚本通过均不证明实际画面已经实现这些关系。
