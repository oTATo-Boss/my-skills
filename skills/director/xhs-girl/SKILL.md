# xhs-girl

目标是用户点赞流里的颜值、穿搭与氛围照片。库内有 **192 张参考图（115 张截图裁图＋77 张完整原图）、八维视觉索引和 17 种画面类型**。从本次表达目标出发，分析并选择互补参考，再整合成一个能拍出来的方案，不把某张参考的整套外观搬给每个人物。

先读[导演判断与多图分工](references/director-method.md)；按[八维视觉索引](references/visual-index.md)找图、打开图片，明确每个来源借什么、舍弃什么、怎样适配。设计感来自人物状态、剪裁、姿态、空间与光影之间的具体关系，避免反复退回端正站姿、礼貌微笑或同一套店铺场景。

## 流程

**出片：**
1. 复用用户已确认的人物、妆发、服装、地点与拍法，确定允许设计的部分，以及这次主要展示的状态或关系。先判断目标，不默认运行抽签脚本。
2. 按目标分别检索妆造、场景、背景、表情、动作、构图、光影与质感，再实际看候选图片。常规原创方案用多张互补参考；用户身份图独立保持人物，不用库内脸替换。每张入选图都限定贡献范围，不照搬整图。用户明确要求单图忠实复拍时尊重该边界。
3. 整合所借特征，解决服装锁定、支撑与持机、空间资源、光源及调色冲突。参考[画面类型](references/shot-types.md)与[造型设计](references/styling.md)作设计辅助；outfit 可查[身材展示](references/silhouette-studies.md)，裁切和实际景别必须容纳展示重点。参考卡不是固定图号套餐。
4. 同一组默认同地点、同时间、同主光、同妆造与后期；靠观看距离、机位和动作事件展开。独立照片按用户任务分别设计。复用现场两三处环境锚点，没有镜子、桌面等资源时调整拍法，不能为迁就类型擅自换地点。
5. 从已经成立的画面关系反推下面的现有提示词。实际生图遵守当前会话工具偏好，未指定时用 Codex 内置生图；只有明确指定 Flow 或 Nano Banana 时才读本机 `flow-image`。默认 3:4，用户比例优先。只给实际上传的身份、造型或必要参考图片编工具输入序号，不自动上传整个参考库。
6. 有成片后用 `python3 scripts/compare_sheet.py 成片1 成片2 --refs R31 R45 --output 对照图.jpg`，将例示图号替换为本次实际借用的相关参考，按[审片与返修](references/review.md)检查每个维度及整合效果。随机六图不能代替相关对照。

**只出造型方案或造型板：**
1. 根据人物锁定项、表达目标与可见的造型参考，读[造型设计](references/styling.md)，设计具体配色、剪裁、材质和饰品位置。多图分别研究所需部件及关系，再检查整体相容性。
2. 需要角色多视图时结合本机 `character-design`；xhs-girl 提供穿搭审美，character-design 负责造型板表达。
3. 确认后回到出片流程，保持这套造型，重新设计摄影动作和机位。造型板正面站姿不自动沿用到成片。

只要构思或提示词时不启动生图。本轮沿用下面现有输出约定，内部参考分工不强制变成新的交付表格。

**抽签仅用于用户明确要求随机、抽卡或候选探索时。** 可运行 `python3 scripts/plan_set.py --count 张数 [--focus face|outfit] [--scene 地点] [--type 类型]` 或 `--look-only [--direction 风格方向]`；已指定项优先。候选仍须看图、取舍和整合，`--seed` 只供复现。跨任务比较已知近期方案的主要组合，不以换店名当新意；没有历史记录时不承诺绝不重复。

## 提示词模板

自然语言通常每张 200–350 字，必要时增加；用户指定结构或联用 Skill 的完整格式优先。按顺序描述画面中可见的内容：

1. **类型与持机关系。** 比例、自拍/朋友拍/镜照、景别、人物占幅和机位；从类型卡取句并适配场景。双手做动作时应由朋友拍或固定手机。
2. **人物与造型参考。** 说明各图用途，例如“图1用于保持五官、脸型与肤色；图2用于保持已确认的妆发、服装、饰品。不复制参考板背景、文字和排版”。未授权换发色、刘海时不自动改变。仅对用户要求重新设计的部分写变化。
3. **妆发。** 写实际可见的眼妆、腮红、唇色和发型。精致程度跟随选定参考；无需每次美瞳、浓腮红或帽子。避免“大眼小脸、冷白皮”等强制改变身份的固定句。
4. **穿搭与展示重点。** 写剪裁、材质、长度和穿法；简洁款靠贴合、收省、领口和肩胯姿态成立。身材重点服从衣服与画幅，长裤、长外套和连衣裙均可，不强制露腿。
5. **动作。** 明确视线、表情、支撑点及手的位置；道具与动作有关才加入。手势不都要贴脸，身体姿态也能成为中心。
6. **场景。** 复用两三处可辨的环境锚点和相对位置，说明同一套现场光。桌沿、窗框、砖缝、座椅等让人物确实处在环境里。
7. **质感。** 指定整组调色与适度皮肤修饰，保留五官结构和原肤色。手机普通拍照的近距透视，附近环境细节可辨，远处自然减弱；不统一加长焦浅景深、灯球、鱼眼或人像模式边缘糊。

手机风格是创作方向，不能仅从截图认定原作者设备。直闪允许远处偏暗，暗调允许脸部偏暗；这些都不等于把背景抹糊。

## 例子：已确认造型后的同地点出片

> 一张 3:4 竖图，朋友坐在近处用手机拍她侧倚扶手椅，人从头到屈起的小腿占画面主要部分。图1保持人物五官、脸型和肤色，图2保持已确认的灰蓝斜肩针织裙、黑色短发、银耳钉和豆沙唇妆；不复制造型板排版。她斜靠棕布椅背，一只手扶着椅沿，另一只手拢头发，双膝朝画面右下方收拢，肩胯错开，裙子的收腰和侧面轮廓清楚。左侧仍是黑框格窗与米色窗帘，右下露出同一张木桌的桌角，日光从左侧进来。灰蓝与暖棕调色，皮肤适度精修而五官不变；椅面织纹、窗框和桌角仍可辨，保留手机近距透视。

## 与 json-prompt-system 联用

用户指定时，读取它当前完整规则并使用原有完整格式，将本 Skill 的造型、动作、场景和参考观察填入对应字段。不自行创建简化摄影模式、不修改它的 Skill、不绕过格式。具体冲突依据实际规则处理，不预先断言效果一定变差。
