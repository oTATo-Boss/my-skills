# xhs-girl

首要目标是用户点赞流里漂亮、有出片感的颜值、身材与氛围照片。库内有 **406 张参考图（115 张截图裁图＋291 张按源文件原样保存的图片）、八维视觉索引和 17 种画面类型**。从本次表达目标出发，分析并选择互补参考，再整合成一个能拍出来的方案，不把某张参考的整套外观搬给每个人物。

**默认路线是小红书女孩的真实手机照片：自拍、镜自拍或朋友拿手机拍，人物明确知道自己被拍，主动面向镜头展示，穿搭、妆发、身材线条与可辨的生活环境一起成立。** 精致妆容、贴身剪裁、低腰露腹、字母图案、饰品、街景、车内和居家都可按参考与任务使用；自然感来自观看距离、现场光、动作与成像，不要求把服装改保守、环境改空白或颜色改灰。手机感可以包含精修、浓妆、调色与直闪，具体程度跟随本次参考。

导演分析与写真 Skill 的母版／输出方法服务这条路线。只有本次任务明确要求影棚、相机或其他拍法时，才按该要求切换；已确认属于当前任务的拍法继续保持，早先其他 Skill 试用的题材不自动成为后续 xhs-girl 的默认。参考取材先保留吸引点，再解决实际冲突，不为证明原创而逐项删除鲜明特征。

**先定整张图为什么漂亮。** 从实际参考中保留脸与妆感、服装和饰品、漂亮的身体轮廓、人物与背景光色之间相互支持的关系，再作多图整合。流程完整、看镜头、有动作或背景可辨都只是部分条件，不能代替整体美感。

**每次调用都做完整画面设计，再写提示词。** 按[导演方法的设计与选择步骤](references/director-method.md#完整画面设计与选择)形成可比较的方案：人物怎样利用具体空间，姿态怎样与衣服、机位、光色一起产生吸引力。原创任务在允许变化的范围内至少比较两个真正能成立的完整候选，选定后反推 Prompt；候选比较在内部完成，对外仍按用户要的格式交付。站、坐、躺、跪和场景互动都由画面需要决定，不套固定姿势套餐。只看脸、锁定复拍、只做造型等任务按其实际范围设计。

**默认优先近距、近中景。** 让脸和本张要展示的肩颈／腰胯／腿线占据视觉主体，按重点选择头至腰、大腿或膝上的裁切与坐姿取景。全身用于展示整套穿搭、完整腿线或用户明确要求，不把人物占画面高度很大等同于脸和曲线足够醒目。环境选择干净悦目、颜色衬人、材质与穿搭协调的位置，背景保留需要的空间线索；用户明确要旧街、粗粝或其他风格时按该目标设计。

**身份锁定只覆盖有依据的内容。** 头肩身份图不提供完整身材比例，不能据此写“保持原身材比例”；已确认体型与衣服保持，不可见部分按本次目标设计自然协调的体态，不虚构原三围。五官、原肤色及用户锁定发型保持；未锁定的妆容、发丝造型与饰品可按参考设计，用具体眼妆、气色、唇光和人物受光提升出片感。

**默认表演是有意识的凹造型。** 他拍和前置自拍的露脸画面默认直视真实镜头；镜自拍写清看屏幕或镜中镜头的构图关系。人物／穿搭照先选一到两项曲线或比例重点，再通过侧身、肩胯错位、单腿承重、坐姿侧倾、抬臂让出腰侧等具体姿态主动展示，用最终轮廓判断是否好看：肩颈舒展、腰胯弧线连贯、臀腿转折与腿线延伸清楚，服装与受光能显出所选重点；动作名称或推胯幅度不构成通过。手机自然感落实在现场光、生活环境、观看距离和成像质感，人物可以明显在摆姿势、经营眼神和表情。组图里的画外视线作为主动造型变化；用户明确要求抓拍、背影或其他视线时按该任务执行。近脸任务在肩颈与表情范围内设计，不硬塞腰腿。

先读[导演判断与多图分工](references/director-method.md)；按[八维视觉索引](references/visual-index.md)找图、打开图片，明确每个来源借什么、舍弃什么、怎样适配。设计感来自人物状态、剪裁、姿态、空间与光影之间的具体关系，避免反复退回端正站姿、礼貌微笑或同一套店铺场景。

## 流程

**出片：**
1. 先确定本张的美感中心、想呈现的漂亮轮廓与观看距离，再核对身份、妆发、服装、地点和拍法的有效锁定项。主动被拍与镜头交流服务这个画面；先判断目标，不默认运行抽签脚本。
2. 按目标分别检索妆造、场景、背景、表情、动作、构图、光影与质感，再实际看候选图片。常规原创方案用多张互补参考；用户身份图独立保持人物，不用库内脸替换。每张入选图按[逐图核对](references/director-method.md#逐图核对)记下实际看见的关系、它具体改变的设计决定及所影响的成片编号。用户明确要求单图忠实复拍时，记录选择保留的具体关系。
3. 按导演方法完成候选设计与选择，整合所借特征，解决服装锁定、支撑与持机、空间资源、光源及调色冲突。每个候选都具体到能拍成一张图，再比较整体吸引力；不能只给惯用方案补细节、把其他候选概括成风险后淘汰。参考[画面类型](references/shot-types.md)与[造型设计](references/styling.md)作设计辅助；常规人物与穿搭按[身材展示](references/silhouette-studies.md)将展示重点落实到主动姿态、服装边界与机位。裁切与观看距离突出脸和目标轮廓，环境具体参与支撑、框景、线条、光色或材质关系。参考卡不是固定图号套餐。
4. 同一组默认同地点、同时间、同主光、同妆造与后期；靠观看距离、机位和动作事件展开。独立照片按用户任务分别设计。复用现场两三处环境锚点，没有镜子、桌面等资源时调整拍法，不能为迁就类型擅自换地点。
5. 从已经成立的画面关系反推提示词，并按[输出格式](references/output-format.md)选择本次交付内容。实际生图遵守当前会话工具偏好，未指定时用 Codex 内置生图；只有明确指定 Flow 或 Nano Banana 时才读本机 `flow-image`。默认 3:4，用户比例优先。默认生成输入只附用户提供的人物身份图；库内样图用于 Agent 多图分析、提取特征并反推完整提示词，不作为模型图像输入。用户明确指定额外图片作为生成参考时，才按其指定附图并限定职责；“多图取材”、工具支持多图或想提升美感都不构成上传许可。按真实输入另编序号，导出时标明需附附件，不声称已经上传。
6. 有成片先按[审片与返修](references/review.md)检查选定的画面关系是否兑现、小图是否吸引人，淘汰虽满足单项却组合常规或失去设计中心的结果；在已授权范围内针对首要问题调整。再用 `python3 scripts/compare_sheet.py 成片1 成片2 --refs R31 R45 --output 对照图.jpg`，将例示图号替换为本次实际借用的相关参考，检查每个维度及整合效果。随机六图不能代替相关对照。

**提交前逐图核对。** 给每张入选图的设计决定标出最终提交 Prompt 中的原句或 JSON 字段值。发现漏写就补齐，实际未采用的图从入选分工中移出。出图后用同一记录逐项写清兑现情况及画面证据。只交付方案或 Prompt 时，按实际阶段标注。见[参考分工与交付格式](references/output-format.md)。

**只出造型方案或造型板：**
1. 根据人物锁定项、表达目标与可见的造型参考，读[造型设计](references/styling.md)，设计具体配色、剪裁、材质和饰品位置。按逐图核对记录每份来源影响的搭配决定。交付造型板 Prompt 或成图时，再按实际阶段核对原句和成片。
2. 需要角色多视图时结合本机 `character-design`；xhs-girl 提供穿搭审美，character-design 负责造型板表达。
3. 确认后回到出片流程，保持这套造型，重新设计摄影动作和机位。造型板正面站姿不自动沿用到成片。

只要构思或提示词时不启动生图。开始交付前读[输出格式与完整示例](references/output-format.md)。完整企划依次给拍摄企划、参考分工、分张设计、每张完整 Prompt。只要方案给前三部分，只要 Prompt 时把逐图简表和可独立复制的 Prompt 分开。单张适当压缩；明确要求生图则按授权执行并交付实际图片与审片结果，不额外设置方案确认关卡。

**抽签仅用于用户明确要求随机、抽卡或候选探索时。** 可运行 `python3 scripts/plan_set.py --count 张数 [--focus face|outfit] [--scene 地点] [--type 类型]` 或 `--look-only [--direction 风格方向]`；已指定项优先。候选仍须看图、取舍和整合，`--seed` 只供复现。跨任务比较已知近期方案的主要组合，不以换店名当新意；没有历史记录时不承诺绝不重复。

## 提示词模板

以下是提示词内容要点；对外封装遵守[输出格式](references/output-format.md)。默认每个 P 编号下一段连续自然语言，通常 200–350 字，完整表达需要时增加；每条自包含，重复本张必要的共同设定，不能以“其余同上”代替。用户要求详细拆解时使用八模块版；用户指定结构或联用 Skill 的完整格式优先。内容覆盖以下要点，具体顺序服从输出格式或用户指定结构：

1. **类型与观看关系。** 比例、自拍/朋友拍/镜照、景别、人物占幅和机位；先让脸与所选轮廓成为主体，再适配场景。双手做动作时应由朋友拍或固定手机。
2. **人物与造型参考。** 默认写“图1用于保持用户人物的五官、脸型与肤色”，库内观察转成具体妆造、姿态与光色描述；仅用户明确要求额外生成参考时才编图2等并说明用途。未授权换发色、刘海时不自动改变。仅对用户要求重新设计的部分写变化。
3. **妆发。** 按本次美感具体设计可见的眼妆、气色、唇色、发丝与配饰关系，保留用户锁定项；不以笼统“自然、妆发清楚”替代设计。精致程度跟随选定参考；无需每次美瞳、浓腮红或帽子。避免“大眼小脸、冷白皮”等强制改变身份的固定句。
4. **穿搭与展示重点。** 写剪裁、材质、长度和穿法；简洁款靠贴合、收省、领口和肩胯姿态成立。身材重点服从衣服与画幅，长裤、长外套和连衣裙均可，不强制露腿。
5. **主动造型与视线。** 写清她为拍照主动摆出的姿势、具体支撑、肩胯与躯干方向、手的位置，以及哪个动作让哪处曲线／比例可见；露脸他拍与前置自拍明确写“眼睛直视镜头”，只写“看朋友”不足以锁定对视。表情有主动展示的意图，道具和生活动作服务造型。视线与用户明确指定的拍法冲突时按该指定执行。
6. **场景。** 先选颜色、材质、明暗与线条都能衬人的好看位置，再用少量环境锚点交代空间。手机现场感可以来自整洁街景、通透窗面、精心布置的室内或色彩背景，不默认破墙、污渍与粗水泥。
7. **质感。** 按选中样本指定整组调色与适度皮肤修饰，不把低饱和、半哑光或低对比作为所有任务的固定审美，保留五官结构和原肤色。手机普通拍照的近距透视，附近环境细节可辨，远处自然减弱；不统一加长焦浅景深、灯球、鱼眼或人像模式边缘糊。

手机风格是创作方向，不能仅从截图认定原作者设备。直闪允许远处偏暗，暗调允许脸部偏暗；这些都不等于把背景抹糊。

## 与 json-prompt-system 联用

用户指定时，读取它当前完整规则并使用原有完整格式，将本 Skill 的造型、动作、场景和参考观察填入对应字段。不自行创建简化摄影模式、不修改它的 Skill、不绕过格式。具体冲突依据实际规则处理，不预先断言效果一定变差。
