# 在已有项目新增或整合工作流

当用户希望把新工作流放入已有项目，或让已有多个工作流共同服务一个项目时读取。适用于任意业务类型；不规定账号运营、内容制作或其他业务的固定目录。

## 1. 识别根与现状

依据用户目标位置、已有项目规则和实际结构确认 PROJECT_ROOT，不只凭当前 cwd、Git 根或某个 workflows 目录判断。规则根、仓库根和单条工作流目录可能不同，应明确适用范围。信息充分时自行判断，存在会改变修改范围的歧义时才询问。

针对性读取现有 AGENTS.md、CLAUDE.md、agent.md 或项目实际采用的规则入口、项目技能索引、相关配置、已有启动方式及待接入流程。沿用原有规则文件，不为统一名字再造一份。只在真正项目根维护索引，不在任务、素材和交付子目录复制项目规则。

列出当前任务涉及的工作流 ID、定义及入口、输入输出、公共资料和状态位置。保存相关规则／配置及受影响旧流程的基线，区分允许增量修改的文件和应保持不变的资源。已有工作流满足需求时优先复用；发现同名或重复职责先协调，不静默覆盖或复制。

## 2. 最小增量接入

先确定工作流与项目之间的边界，再动手：

- 新增工作流：在符合项目既有约定的未占用位置生成；WORKFLOW_DIR 不一定名为 workflows/xxx，不得把已有 PROJECT_ROOT 传给整包生成器。
- 整合已有工作流：检查真实入口、定义和资源，修正必要的绑定与交接；不无故搬目录、重构旧 Runtime 或重写其运行状态。
- 公共上下文：优先引用已有目标、风格、规则或领域配置；缺失时构建 Agent 自主选择合适文件和内容，不强制 account.yaml、project.yaml 或其他统一业务配置。
- 业务目录：按当前数据与产物决定位置，沿用现有组织方式，不批量创建 data/、content/、reports/ 等空目录。
- 项目规则与索引：只增量登记必要的用途、调用方法和资料位置，不以新模板覆盖旧约定或更改无关全局规则。

## 3. 登记与调用

优先复用项目已有的命令、路由或工作流清单。数量少、人工或 Agent 调用时，可在已有说明／规则中登记；只有实际工具需要机器可读清单时再生成相应配置和读取逻辑。

每条登记至少能回答：何时选它、定义或入口在哪、输入如何准备、输出在哪、怎样查状态及恢复、需要哪些公共资源。保留已有稳定 ID 与别名，调用时不按模糊文件名猜流程。

Agent 根据登记选择入口时，其运行环境应明确加载该项目规则；程序路由需要真实实现参数解析、路径解析、输入传递、退出状态和 run ID 的返回。登记文件本身不启动任务。统一入口必须使用所选工作流的正确工作目录或绝对路径，不依赖用户刚好 cd 到某个子目录。

日常调用走“项目入口 → 对应 Runtime”，不重新进入 Builder。已有手动入口足够时不额外开发调度系统；要求并行、自动串联或定时时再实现相应机制并验证，不能从目录共存推断已具备这些能力。

## 4. 公共资料和跨流程交接

明确哪些资源共享、由谁维护、哪些流程只读、共享写入如何协调。每个工作流保留自己的 run ID、日志、检查点和产物，不共用一份含糊的运行状态。

首版 Runtime 的 rules 与 instructions 路径限制在工作流目录内；不能直接填父级 ../ 规则路径假装能加载。由 Agent 选择版本化快照、显式输入、声明资源或项目适配器读取等真实方式接入公共上下文，记录来源与更新方式，并检查执行器实际收到内容。规则快照只是传递手段，不成为另一份独立维护的公共真相源。

公共配置变更时更新受影响绑定并重新验证；不悄悄改变已有运行的输入或检查点。Skill／规则的“能找到路径”与“被本次执行消费”应分开验证。

跨流程以稳定 ID、已通过验收的产物路径／引用及必要版本信息交接；说明生产方、消费方、格式、选择哪次运行，以及由谁准备下游输入。文件名不充当唯一身份，不让下游随意读取“最新文件”或把整个聊天记录当输入。

每条流程继续在自身输出范围写入产物；需要发布到公共位置时，由明确的发布步骤或项目入口登记引用／复制，保留原始已提交产物与来源，不移动或覆盖受检查点保护的文件。对共享台账采用单一写入者或已有并发控制，具体业务字段由 Agent 决定。

## 5. 接入验收

按任务选择必要检查，保留真实证据：

1. 从项目正常入口和另一个工作目录，都能找到并启动目标流程，输出真实退出状态、run ID 和产物。
2. 每条工作流仍能从自己的入口独立调用，不依赖项目总控聊天或 Builder。
3. 用可区分的公共上下文样例证明信息被实际读取与使用，而不仅检查配置文件存在。
4. 需要交接时，用一个真实上游产物生成下游输入，检查 ID、格式、版本和来源能追溯；缺失或不合格产物不能被当作成功输入。
5. 对受影响旧流程做针对性回归；核对未授权修改的规则、原有产物和历史状态未被覆盖。输入、日志和输出不互相混用。
6. 登记和实际调用一致；把未实现的自动串联、调度或权限能力如实列为缺口。

沿用独立验收中的状态与 ready 门槛。用户只要求设计时，交付接入方案和最小变更范围，不直接改其业务项目。交付时说明项目根、工作流位置、哪些公共文件被复用或补充、如何调用及哪些交接已验证。
