# 独立验收

## 状态不能混用

- designed：需求、步骤、能力绑定和验收已明确。
- generated：项目文件与真实入口已生成。
- configured：所需依赖、账户及工具配置完成，并保存探测范围。
- verified：已运行相应样例，结果有证据。
- ready：以下全部必要场景通过，且业务产物达到约定标准。

生成器默认只写 generated。runner 的 succeeded 只表示某一次运行通过自己的验收；它不会给所有业务场景或整个交付包颁发 ready 证明。

## 每个生成工作流的测试

在新进程／新原生会话中仅使用项目入口、定义与声明依赖，关闭对 Builder 聊天上下文的依赖：

1. 正常运行真实样例，检查每步输入输出及最终业务产物。
2. 受控失败时，保留准确错误、尝试日志和状态，不让下游错误通过。
3. 一次暂时性失败后重试成功；持续失败耗尽预算后停止。显式 retry 不绕过次数上限。
4. 在已提交检查点暂停或终止进程，之后由新进程 resume，已通过上游不重复执行。
5. 中断副作用节点时不自动重放未知结果；父进程被强制结束但子进程仍活着时也不重复启动。
6. 输出不合格时，即使执行器退出 0，节点或最终验收仍失败。
7. 再次 run 使用新 ID 和隔离输出，结果不借助上次聊天历史。
8. 需要自动触发时，实际验证调度与 Runtime 链路。

文件、定义、代码或资源版本变化后，旧检查点应被拒绝或由明确迁移处理。验证真实产物被篡改时不能继续报告当前验收通过。

故障注入放在隔离测试资源或测试适配器中，外部真实动作只使用已授权样例。模拟 probe 或模型适配器通过不证明真实服务、认证或模型调用已经工作。

## 交付记录

记录定义版本、代码／资源锁及验证器摘要、执行环境、命令、样例、run ID、错误、产物和验收结果。区分覆盖了哪些 Runtime 能力、哪些业务质量和哪些外部连接；列出未完成项及恢复方式。

交付项目必须有真实测试，不以空 tests/ 或清单文档冒充已测试。生成器的 acceptance-plan.md 仅提醒待补场景，Builder 应针对用户目标补齐可执行测试。

Skill 开发者的黑盒回归位于源码仓库 docs/workflow-builder/tests/，不作为生成项目测试的替代，也不随 Skill 分发。复杂业务采用具体样例进行前向评估，而非仅匹配提示词文本。

## 接入已有项目

除独立 Runtime 验收外，按 [项目接入要求](project-integration.md)核对项目入口能真实调用、公共上下文被消费、必要的跨流程产物能交接，以及受影响旧流程没有回归。具体目录与配置由项目需求决定，不以生成固定文件清单作为通过标准。
