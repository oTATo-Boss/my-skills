# 运行适配器

## 首版能力

随包 Runtime 为 Python 3.10+ 的 POSIX JSON 子进程执行器，在 macOS/Linux 使用 flock 单运行锁和进程组清理。
它已实现顺序 DAG、脚本和 JSON 子进程 Agent 接口、规则与 Skill 文本传递、前置资源 probe、超时、有限重试、检查点、运行记录和产物验收。

原生 Codex／Claude Code／Cursor 适配器、内置模型调用、并行、条件分支、无人值守调度、分布式锁、Windows 支持及权限沙箱不包含在该实现中。工作流需要时必须真正接入相应机制并独立验证，不能仅更改 adapter 名称。

## JSON 进程协议

stdout 只能返回一个 JSON 对象，stderr 用于诊断；退出非 0 为执行失败。stdin 包含：

- protocol_version、workflow_id、run_id、step_id、attempt。
- inputs：由绑定解析出的本节点命名输入。
- project_dir、output_dir：项目和本次产物目录。
- idempotency_key：同一运行同一节点的稳定键，重试不变。
- rules：已读取的项目业务规则。
- agent：Agent 节点的 role 与 instructions 文件内容；节点必须显式声明 role。
- resources：本节点绑定的 Skill 文件文本及其他资源的非敏感声明。

Agent 适配器是项目内可运行程序，负责把这些信息转成模型请求，使用已声明的真实工具和认证，解析结果并返回契约要求的 JSON。Runtime 并不因 kind=agent 就自动创建模型 Agent；它和脚本使用同一可测试进程接口。

当前实现继承启动环境，工具范围只是业务约定，不能替代平台权限。需要真正隔离时使用具备能力限制的执行环境。不要把已有 UI 插件连接自动视为子进程中的 MCP 连接；应在目标执行环境配置、探测和测试。

## 其他平台的接入步骤

检查目标版本官方文档、项目和实际工具，列出 check／run／status／retry／resume／validate 的真实映射。先确认调用入口、输入输出、凭据、项目规则与 Skill 加载方式，再写适配代码和失败处理；拒绝虚构客户端 CLI。

维护能力矩阵，分别标注可用、缺配置、缺授权、不支持、未验证。每项应有对应探测或测试证据。若原生执行无法跨会话恢复，用持久脚本补足或选择混合方式。

自动触发按用户需要接已有调度机制，声明触发条件、参数、身份、重复触发和并发策略、失败反馈与停用方式。实际验证调度触发到 run_id 的关联；手动运行通过不能证明后台机制可用。

## 恢复边界

每次运行保存 state.json 和事件日志，节点尝试保存 stdout/stderr。通过节点记录输出及产物散列；runtime/、scripts/、agents/ 中的源码、规则、Schema、资源锁、执行／验证命令直接引用文件和已声明资源文件参与恢复指纹，凭据值不入状态。

其他位置的隐式依赖要显式列入 resource.paths 或放进标准源码目录，不能假定 Runtime 能推断任意程序的全部导入与文件读取。无关新输入不参与源码指纹；本次输入单独保存并校验摘要。实际 Python、PyYAML 和 jsonschema 版本也绑定到检查点。

新进程先取得运行锁、检查定义与产物一致性，再继续。被杀死的父进程可能留下子进程；Runtime 保存执行 PID，仍存活时拒绝重放。结果未知的 manual 节点需要先核对外部系统，不能编辑状态假装完成。

节点重入只在原预算内发生。已通过上游不重复运行；改动源码或已提交产物后首版要求新 run。没有通用补偿事务或 exactly-once 保证。
