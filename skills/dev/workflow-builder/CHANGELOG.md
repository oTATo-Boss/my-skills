# 版本记录

## 0.2.1 — 2026-10-28

- 明确已有业务项目中新建、开发或导入的完整工作流统一存放在项目根 workflows/<workflow-id>/，与 skills/ 的整包组织逻辑一致。
- 区分外部导入与项目内整合；默认复制完整源码和必要资源并修正绑定，不以外部引用代替导入。
- 补充副本完整性及不依赖原始工作流目录的验收要求；业务资料目录仍按需求决定，Runtime 保持 0.1.0。

## 0.2.0 — 2026-10-28

- 增加在已有项目新增或整合工作流的任务模式，区分项目根与单条工作流目录。
- 按需复用规则、公共资料与调用入口；由 Agent 决定业务配置及目录，不强制账号类模板或通用登记文件。
- 补充真实路由、共享上下文传递、跨流程产物交接及受影响旧流程回归的验收要求。
- 随包生成器、Schema 和 Runtime 继续使用 0.1.0；本次不添加统一调度器或改变其能力声明。

## 0.1.0 — 2026-10-28

- 总控需求拆解、分级本机能力发现、缺口搜索、接入和交付；按需组合三个已有伙伴 Skill。
- 标准化 workflow.yaml 与节点契约，提供独立项目生成器及 POSIX JSON 子进程 Runtime。
- 支持前置探测、规则与 Skill 文本传入、顺序 DAG、产物验收、持久状态、有限重试、运行锁及新进程恢复。
- 提供可运行笔记报告示例及源代码仓库中的正常、失败、重试、恢复和独立运行验证。
- 首版不含原生模型客户端、并行／分支、后台调度或 Windows 适配；这些能力需要按目标项目实现并验证。
